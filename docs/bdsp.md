# ブリリアントダイヤモンドとシャイニングパール

ブリリアントダイヤモンドとシャイニングパールは、ILCA が Unity で作成しており、IL2CPP の
ゲームコードが Pia 上で直接動いています。

フランス語版のシャイニングパール (バージョン 1.3.0) を基準に、ユニオンルーム (ポケモンセンター2F、
左側の係員、普通の「はい」) と、ちかつうろで測定しました。

## 状況

市販の実機で動作しているもの。

- `prod.keys` と LDN のパスフレーズだけで本体のセッションに参加できている。すべてのパケットを
  復号済みで、送信経路は本体自身の暗号文とバイト単位で一致する。
- Local、Mesh Station、Mesh Protocol のハンドシェイク、RTT タイマー、両方向での
  信頼性のある転送。
- 市販のユニオンルームでキャラクターが歩き、交換のエモートを表示し、ゲーム本来の
  挨拶の会話をプレイヤーに対して実行する。
- 交換を最後まで完了。本体のオファーを受け、組み立てたポケモンを受理し、セーブを書き込んだ。
  交換は1回のアソシエーション内で連続して行える ([交換](bdsp_trade.md#the-completed-trade))。
- ホスト機能。ユニオンルームに入った本体が、pokeldn がホストするルームに参加し、キャラクターを
  描画して、そのルームと交換を完了する ([ホスト](bdsp_session.md#hosting))。
- 組み立てたボールカプセルをユニオンルームで交換し、本体はプレイヤーが所持しているシールと一緒に
  それをコレクションに保存する ([プロトコルのページ](bdsp_protocol.md))。
- レコードミックスとバトルロビーが、本体のレコードと選んだ6匹のポケモンまで動く。
- ちかつうろの床面でキャラクターが歩き、本体のひみつきちの内容を読み出せている。

## 未解決

- 本体の画面で挨拶の名前が差し替えられる件
  ([挨拶の名前](bdsp_protocol.md#the-name-in-the-greeting))。
- バトルの募集がされていない状態で 0x08 が市販の本体に届いたとき、本体に何が表示されるか。
  コードはアドレス 0x18 に null チェックなしで書き込み、ゲームのモジュールにはユーザー例外ハンドラーがない。
  これまで送った 0x08 は、信頼性のあるウィンドウが既に見たシーケンス ID で送信されていたため、
  この経路には届いていない ([バトルラダー](bdsp_protocol.md#the-battle-ladder))。
- ちかつうろのセッションのホストではない市販の本体が、pokeldn からの 0x61 を受け入れるかどうか。
  測定したちかつうろのセッションでは本体がホストだった。pokeldn はそのようなセッションをホストしない。
  共通のディスパッチと `UgNetworkManager` のハンドラーには、送信者のフィルターがない
  ([プロトコルのページ](bdsp_protocol.md#the-grand-underground))。
