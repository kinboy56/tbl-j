# ふしぎなおくりものファイル

`.pokegift` ファイルには、ファイアレッド・リーフグリーン向けまたはソード・シールド向けのふしぎなおくりもの配信を一式、
または FRLG の ARM コンソール用ペイロードを、対象ゲームとネイティブのレコードとともに保存します。

## デスクトップアプリ

ゲームごとに、ふしぎなおくりものは 1 つのツールで、ギフトの選び方は 3 通りです。ソード・シールドでは 4 通りです。
1 つのビルダーで両方のゲームを扱い、各ゲームのモジュールがプリセットとフォームを提供します
（`pokeldn/frlg/gift/builder.py`、`pokeldn/swsh/gift_builder.py`、`pokeldn/app/gift_builder.py` で結び付けられています）。

| モード | 送信内容 |
|---|---|
| プリセットを使う | 内蔵のギフト。FRLG のふしぎなカード、ふしぎなニュース、コンソールコードは、フラグとしてランチャーに渡されます |
| 公式イベント | 実際のソード・シールドのイベントカード（[公式イベントカード](swsh_gift.md#official-event-cards)）。作成済みのギフトと同様にコンパイルされます |
| 自分で作る | フォームの内容を Start 時に `session/gifts/<tool>.pokegift` にコンパイルし、`--gift-file` で渡します |
| ファイルを開く | 共有された `.pokegift`、またはソード・シールドでは `.wc8` |

FRLG のゲームブーストは常駐フックです（[`install-resident`](frlg_rom.md#install-resident)）。
同時に複数をチェックでき、それらは 1 つのチェーンとして動作します（[複数のフックを同時に使う](frlg_rom.md#several-hooks-at-once)）。
各ブーストには設定があり、それらはランチャーの `--resident-param` フラグになります。パネルには、チェックしたセットが
コンソールの 1024 バイトのうち何バイトを使うかが表示されます。

| ブースト | 設定 | パラメータ |
|---|---|---|
| ゲームを高速化 (`turbo-lite`) | 速度 x1 から x4。フィールド、バトル、または両方。常時オン、または R、B、Select を押している間だけ。テキストを速く表示 | `field` と `battle` = 速度 - 1、x3 以上で `budget=228`、`hold`、`extra=4` |
| 壁抜け | R、B、Select のいずれか | `hold` |
| 色違いカウントダウン | 減速ボタン。x2、x4、x8 の減速 | `slow`、`slow_frames` は 1、3、7 |
| 野生ポケモンとの遭遇なし、先頭ポケモンの個体値の画面表示、ポケモンのフォロワー | なし | |

L は提供されていません。フックが抑止するフラグを持つのは R のヘルプシステムの切り替えだけです。後で使うためにブーストを保存する場合は、
`install-resident` の代わりに `save-write --resident` を送ります。セットは `filler_B20` に入り、同じセッションでインストールされます。
1 回の `install-resident` セッション（876 バイト）を超えるセットと、フォロワーは、
常にセーブ経由です。ママによるブーストの復元は、ママのローダーを紐づけ、ママに話しかけると、
どの起動の後でも、セーブが持つセットをインストールします。ブーストを再び送ると、動作中のセットが置き換わります。
アプリは、セーブのオプションの横と「Before you send」の画面に、保存が必要なセットも含めて復元の手順を表示します。
プリセット名と説明は折り返し、手順が見えたままになるようにしています。
`tests/test_gift_builder.py` は、ブーストのすべての組み合わせと各設定を、ランチャー経由で
12 本すべてのカートリッジについて送ります。

セーブの読み取りでは、トレーナーID (TID) とシークレットID (SID)、トレーナーの詳細とプレイ時間、そして
最後に保存された手持ちポケモンの性格、個体値、努力値を読み取れます。結果はセッションログに表示され、2 つのダンププリセットは
読み取ったデータを Received にも書き込みます。この欄では、通常は表示されない SID、0 から 31 の 6 つの個別の値としての個体値、
努力値をトレーニングポイントとして説明します。これらの読み取りは、セーブとふしぎなカードを保持します
（[セーブの読み取り](frlg_rom.md#reading-the-save)）。

ネイティブの `.wc3` と `.wc8` の拡張子は、JSON の判定より前にゲームのバイナリリーダーを選びます。
WC8 のバイナリシールは `{` で始まることがあり、その場合もネイティブのレコードのままです。`.pokegift` ファイルは
JSON リーダーを使います。JSON の開き括弧を持つ不明な拡張子のファイルも、共有されたギフトを保持できます。

Customize はプリセットをフォームにコピーします。FRLG のカードのプリセットは、フォームですべての手順を表せる場合にだけ、これを提供します。
つまり、ポケモン、アイテム、タマゴ、野生バトル、メッセージの各手順がすべて無条件の段階であり、
イベントスクリプトと訪問トレーナーがないことです。ソード・シールドのプリセットは、すべてフォームの状態になります。

FRLG のフォームは、ふしぎなカード、ふしぎなニュース、またはコンソールコードを作成します。

| 部分 | 内容 |
|---|---|
| カード | タイトル、サブタイトル、4 行のテキスト、アイコンのポケモン、カード ID 1000 から 1019、再受け取り可、共有可 |
| 渡す相手 | どのポケモンセンターでも配達員、プレイヤーの家のママ、またはマサラタウン南の男性 |
| 手順 | ポケモン（種族、レベル、持ち物、4 つのわざ）、アイテムと数量、タマゴ、野生バトル、メッセージ |
| ニュース | タイトル、最大 10 行、ニュース ID |
| コンソールコード | ARM のソース、またはビルド済みの `.bin`、対象のカートリッジ、期待される答え、返されるバイト列 |

各手順は独立した配信段階なので、手持ちかバッグがいっぱいの場合は、その手順で止まり、プレイヤーは
残っている分だけ再試行します。配達員以外の人物は、`initramscript` の紐づけを通じて手順を保持します。紐づけられている間は、カードは表示されません。
紐づいたスクリプトには受け取りフラグがありません。そのため、別のギフトが紐づけを置き換えるまで、その人物は毎回手順を渡します。種族は、カートリッジの
内部番号を使います（`pokeldn/frlg/save/species_names.py`）。カードとニュースは 4 本すべてのカートリッジ向けにコンパイルされます。コンソールコードは、
4 本すべて、または選んだ 1 本向けにコンパイルされます。

コンソールコードは、`arm-none-eabi-as` が PATH 上、Homebrew のフォルダー、または Arm の Windows インストールフォルダーにあるとき、それでアセンブルされます。
それがない場合、フォームはビルド済みの `.bin` を受け付け、このシステムでアセンブラーをインストールするコマンドを表示します。
システムごとのコマンドは次のとおりです。

| システム | コマンド |
|---|---|
| macOS | `brew install arm-none-eabi-binutils` |
| Fedora | `sudo dnf install arm-none-eabi-binutils-cs` |
| Debian、Ubuntu とその派生 | `sudo apt install binutils-arm-none-eabi` |
| Windows | `winget install Arm.ArmGnuToolchain` |

その他の Linux ディストリビューションでは、Arm のダウンロードページが案内されます。Fedora 44 と Ubuntu 24.04 のパッケージは、
既定のテンプレートを `01 00 a0 e3 1e ff 2f e1` にアセンブルします。オフラインチェックは、シミュレートされたコンソール上でコードを 1 回実行し
（`pokeldn/frlg/rom/custom_code.py`）、答えとバイト列を表示します。同じチェックは Start の前とファイル保存の前にも実行されます。
フォールトするコード、または 1 を返さないコードは拒否されます。

ソード・シールドのフォームは、ポケモン（選んだ、またはランダムの性格。任意でキョダイマックスできるように設定することもできる）、タマゴ、
最大 6 個のバッグのアイテム、公式の衣装、バトルポイントまたはお金を、カード ID とともに作成します。ポケモン、タマゴ、アイテム、衣装、
バトルポイントの種類は、実機のソードで出品されて引き換えられたレコードのバイト列を書き込みます
（[ソード・シールドのふしぎなおくりもの](swsh_gift.md#a-card-delivered-to-a-retail-console)）。ピカチュウのプリセットは、
ランチャー自身の既定のレコードとバイト単位で同一です。衣装は、公式の衣装カードのペアから得られ（[衣装](swsh_gift.md#clothing)）、
プレイヤーの性別ごとに最大 6 点です。PKHeX は、キョダイマックスのフォームがない種族へのキョダイマックスフラグを拒否します。

Before you send では、コンソールが受け取るもの、実行されるタイミング、そのギフトが対象とするカートリッジを一覧します。Save gift file は、選んだギフトを、
ボードも Switch のキーも含めずに `.pokegift` として書き出します。FRLG のプリセットは、ランチャー自身のビルダーを通るため、ファイルには
そのビルドが生成するすべてのカートリッジの版が入ります。コンソールのゲームコードは、ギフトのハンドシェイクの間に版を選びます。ファイルにないカートリッジは、
ギフトのデータを送る前に拒否されます。プリセットのカード ID は Advanced タブにあります（`--flag-id`、1000 から
1019）。

アプリは、読み込み時にギフトファイルを変更しません。ファイルは選んだパスに残ります。

実機で開いたファイルから配信できたものは、フランス語版ファイアレッドでのセレビィのカードとコンソールコードのファイル、
ソード上のピカチュウのカードです。フォームで作成したコンソールコードは、セーブのトレーナー ID で応答しました。

## コマンドライン

どちらのギフトランチャーも `--gift-file FILE` を受け付けます。ソード・シールドは `--record` を別名として残しています。
`--export-gift FILE` は、選んだギフトを保存し、無線を使う前に終了します。

```bash
./.venv/bin/python bin/frlg_mg_host.py --gift celebi --export-gift celebi.pokegift
./.venv/bin/python bin/frlg_mg_host.py --news berry --export-gift news.pokegift
./.venv/bin/python bin/swsh_gift_host.py --species 25 --level 25 --export-gift pikachu.pokegift
./.venv/bin/python -m pokeldn.gifts inspect celebi.pokegift
```

FRLG のギフトファイルは、カードのフラグ ID、スクリプト、アンケート、拒否メッセージをまとめて定義します。
`--flag-id`、`--questionnaire`、`--hunt-*` などのペイロードの上書きは、ファイルと一緒に指定すると拒否されます。
無線、トレーナーの識別情報、カートリッジの選択のオプションは、引き続きセッションの設定です。

### コンソールコード

内蔵ペイロードを、設定済みのバイト列と応答の設定とともに書き出します。

```bash
./.venv/bin/python bin/frlg_mg_host.py --buffer-script save-dump --dump-size 64 \
  --export-gift save-dump.pokegift
```

作成者は、明示的なカートリッジの対象を付けて、独自の生の ARM コードをパッケージ化できます。

```bash
arm-none-eabi-as -march=armv4t -mcpu=arm7tdmi -o payload.o payload.s
arm-none-eabi-objcopy -O binary -j .text payload.o payload.bin
./.venv/bin/python -m pokeldn.gifts import --game frlg --code payload.bin \
  --build BPRF --name "Custom payload" --expect 66 -o custom.pokegift
```

最小の `payload.s` は、応答のパラメータに 66 を書き込み、1 回の呼び出しで完了します。

```asm
.syntax unified
.arm
.text
.global _start
_start:
    mov r3, #66
    str r3, [r0]
    mov r0, #1
    bx lr
```

コードは位置独立の ARMv4T で、ワード境界に揃えられ、最大 1024 バイトでなければなりません。コンソールは
`r0 = &param`、`r1 = gSaveBlock2Ptr`、`r2 = gSaveBlock1Ptr` を渡し、1 が返されるまで、フレームごとにペイロードを呼び出します。
実行の契約は [コンソールコード](frlg_rom.md) を参照してください。`--expect` がない場合、返された任意のパラメータを受け付けます。
バイトバッファへ応答を向け直すペイロードは、パッケージ化するときに `--dump-size N` を使います。

`.pokegift` ファイルを共有します。受け取る人は、FRLG のふしぎなおくりもので開くか、
`--gift-file custom.pokegift` 付きで起動できます。`--dump-file PATH` は、ホストが返されたダンプを書き込む場所を選びます。
カートリッジの版は、コードを送る前に強制されます。パッケージ化は構造とサイズを検証します。
作成者は、実機での実行の前に、新しいペイロードを `buffer_script.emulate_repeating` でオフライン実行しなければなりません。
ファイルのハッシュは、ネイティブのコードが返ること、またはセーブを壊さず残すことを証明しません。

### ネイティブ形式

変換器は、ソード・シールドの WC8 レコード、FRLG の `.wc3` ファイル、`pokemon-gen3-mysterygift-tool` で使われる FRLG のペアファイルを取り込みます。
`.wc3` と `.wc8` は、アプリの Open a file と `--gift-file` で直接開くこともできます。

到達可能なコードに絶対アドレスを含まない FRLG のスクリプトは、同じカードのレイアウトで各カートリッジに対応できます。
そのジャンプとテキストは、`setvaddress` [scrcmd.c:171] からの相対位置にある `vgoto`/`vmessage` のオペランドであり、アイテムは `callstd` を通ります。
`goto`、`call`、`message`、`callnative`、その他の絶対ポインタを含むスクリプトは 1 つのカートリッジに属し、`--build` を必要とします。
その種類の `.wc3` は、直接開こうとすると拒否されます。

```bash
./.venv/bin/python -m pokeldn.gifts import --game swsh --record event.wc8 -o event.pokegift
./.venv/bin/python -m pokeldn.gifts import --game frlg --wc3 "FL - Item AuroraTicket (FRE).wc3" -o aurora.pokegift
./.venv/bin/python -m pokeldn.gifts import --game frlg --card WonderCard.bin \
  --script Script.bin --name "Event gift" -o event.pokegift
./.venv/bin/python -m pokeldn.gifts export celebi.pokegift --build BPRF --out-dir native-gift
./.venv/bin/python -m pokeldn.gifts export celebi.pokegift --wc3 --build BPRJ --out-dir native-gift
./.venv/bin/python bin/frlg_mg_host.py --gift celebi --console-build BPRJ --export-gift celebi.wc3
```

`.wc3` または `.wc8` で終わるパスに保存すると、`.pokegift` ではなくそのネイティブファイルが書き出されます。対象は
`--export-gift`、Save gift file、`pokeldn.gifts.save` です。`.wc3` には 1 つのカートリッジのカードとスクリプトが入ります。`--build` がなければ、ギフトのすべての版が同じバイト列を持つ必要があります。GUI は、
版が異なる場合に書き出すカートリッジを尋ねます。`.pokegift` はすべての言語の版を保持します。`.wc3` のメタデータブロックは、
アイコン以外がゼロで書かれ、アイコンはカードのアイコンを繰り返します。
ゲームが受け付ける国際版のギャラリーファイルは、取り込みと書き出しの後も、同じカード、スクリプト、アイコンのバイト列に戻ります。

国際版の `.wc3` は 1420 バイト（`0x58C`）で、構造は次のとおりです。

| オフセット | サイズ | 内容 |
| --- | --- | --- |
| `0x000` | 336 | カードの CRC16、パディング 2 バイト、332 バイトの `struct WonderCard` |
| `0x150` | 80 | セーブ側のカードのメタデータ。読み取りはされない |
| `0x1A0` | 1004 | CRC16、パディング 2 バイト、`struct RamScriptData`（magic 51、マップグループ、マップ番号、オブジェクト ID、995 バイトのスクリプト）、パディング 1 バイト |

Project Pokemon の EventsGallery にある国際版ファイル 54 本すべてでは、ファイル内のスクリプトの CRC はパディングを含む 1000 バイトを対象とします。
ゲーム自身の CRC は 999 バイトを対象とします [script.c:488]。取り込みはどちらも受け付けます。
取り込み時の `--icon N`、またはアプリの Open a file 下の Card icon は、カードの `iconSpecies`
（カードのオフセット 2）を、0 から 411 の内部種族 ID に設定します。0 の場合はアイコンを描画しません
[mystery_gift_show_card.c:466]。

日本語版の `.wc3` は 1252 バイト（`0x4E4`）です。カード構造は 164 バイト、その CRC のラッパーは 168 バイトで、
メタデータは `0x0A8` から、1004 バイトの RAM スクリプト構造は `0x0F8` から始まります。
直接取り込みでは、日本語版ファイルは `BPRJ` と `BPGJ` の候補になり、国際版ファイルは 10 種のラテン文字版カートリッジの候補になります。
明示的な `--build` はカードのレイアウトと一致しなければなりません。ギャラリーの
フラグ ID 4 から 8 のデバッグ用カードは拒否されます。配達員がギフトを渡すのは、フラグ ID 1000 から
1019 のものだけだからです [mystery_gift.c:241]。オーロラチケットとミスティックチケットは、最初の殿堂入り以降のセーブでは効果がありません（
[オーロラチケットとミスティックチケット](frlg_gift.md#the-aurora-and-mystic-tickets)）。

FRLG のペアには、336 バイトの国際版カードまたは 168 バイトの日本語版カードと、1004 バイトの RAM スクリプト構造が含まれます。取り込みでは、両方の
CRC と、紐づけられていないふしぎなおくりもののヘッダーを検証します。ネイティブのペアは、スタンプ、訪問トレーナー、
Mystery Event のスクリプト、アンケートの条件、ふしぎなニュースを持てません。そのペアへの書き出しは、これらの追加要素を含む配信を拒否します。
`.pokegift` はそれらをまとめて保持します。

## バージョン 2

ファイルは UTF-8 の JSON で、必須フィールドは 5 つあります。

| フィールド | 値 |
| --- | --- |
| `format` | `pokeldn.gift` |
| `version` | 整数 `2` |
| `game` | `frlg` または `swsh` |
| `name` | 空でない表示名、最大 180 文字 |
| `variants` | 対象コードを、ネイティブのデータとオプションに対応付けるオブジェクト |

各版は `data` と `options` のオブジェクトを持ちます。`data` のコンポーネントは、ネイティブのバイト列を 16 進数で表した `hex` と、
その小文字の SHA-256 ダイジェストである `sha256` を持ちます。JSON のフィールドの順序に意味はありません。
書き出しは、決定的なファイルにするためにフィールドを並べます。

| ゲーム | 版のキー | データのコンポーネント | オプション |
| --- | --- | --- | --- |
| FRLG のギフト | 対応するカートリッジのコード | `card`、`ram_script`、`stamp`、`activation_script`、`install_activation_script`、`trainer`、`news`、`mevent` | `questionnaire`、`denied_message` |
| FRLG のコンソールコード | 対応するカートリッジのコード | `buffer_code`、`buffer_lead_1`.. | 下記の応答設定 |
| ソード・シールド | `swsh` | `wc8` | なし |

FRLG のカードの版は、同じフラグ ID とギフトの種類を持ちます。ふしぎなニュースとコンソールコードは、それぞれ単独で運ばれます。
キャプチャ、キー、ファイルシステムのパス、セッションのタイミングは、この形式の対象外です。

FRLG のコンソールコードの版は、`buffer_code` コンポーネントをちょうど 1 つ持ちます。その前に、最大 8 個のペイロードを
同じセッションで、`buffer_lead_1`、`buffer_lead_2` と続く番号で、欠番なく実行できます（セーブに保持された常駐フックは、それらとともに `filler_B20` を書き込み、その後インストールします）。任意の応答設定は、
`buffer_expect`（32 ビット符号なし整数、または `trainer-id`）、`buffer_dump_size`、
`buffer_dump_blocks`、`buffer_dump_address`、`buffer_dump_addresses`、`buffer_decode` です。
ダンプのサイズはブロックあたり 1 から 1024 バイトで、最大 32 ブロックです。分散ダンプでは、ブロックごとに 1 つのアドレスを指定します。デコーダー名は既存の応答デコーダーに由来します。ダンプの出力パスとローカルの ROM 比較パスはホストに残り、共有ファイルからは除外されます。

リーダーは、カード、ニュース、WC8 を含むバージョン 1 のファイルも受け付けます。書き出しはバージョン 2 を使い、
コンソールコードと整数の応答設定を追加します。バージョン 1 のリーダーは、バージョン 2 のファイルを拒否します。

リーダーは、未知のバージョン、フィールド、対象コード、重複する JSON フィールド、不正なハッシュ、
256 KiB を超えるファイル、不正なネイティブのサイズ、不正なコンポーネントの組み合わせを拒否します。FRLG の検証は、
カードのフィールド、トレーナーのチェックサム、Mystery Event の終端も確認します。ソード・シールドの配信は、無線を開く前に、
共通の PKHeX ギフト検証を引き続き必要とします。

ハッシュは破損したバイトを検出します。配布者を認証するものではなく、取り込んだ FRLG スクリプトが安全に実行できることを証明するものでもありません。
ネイティブスクリプトの取り込みは命令を保持し、明示的なカートリッジの対象を必要とします。

## 実装

`pokeldn.gifts` は、エンベロープ、検証の振り分け、リーダー、ライター、変換器を担います。ゲーム固有のコーデックは `pokeldn.frlg.gift.file` と `pokeldn.swsh.gift_file` にあります。共有のアプリのアダプターは、
ランチャー自身のビルダーを呼び出します。GUI は、両方のゲームで 1 つの選択と書き出しのコントロールを使います。

FRLG のファイルアダプターは、既存の `MysteryGiftDistribution` を、そのカートリッジの選択と拒否の経路を含めて組み立てます。ソード・シールドのアダプターは、既存の WC8 アドバタイズ用ビルダーを提供します。
無線のプロトコルとペイロードのレイアウトは変更されていません。
