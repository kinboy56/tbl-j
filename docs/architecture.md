# コード構成

GUI と CLI は、ツールのプリセットとポケモンの準備を共有します。ゲームのモジュールは実測済みの
通信フォーマットとタイミングを保持し、共有コンポーネントはゲームのディレクトリの外に置きます。

| 場所 | 役割 |
| --- | --- |
| `pokeldn/app/` | ツールのカタログ、引数の組み立て、パーサーの検査、設定、パス、子プロセス |
| `pokeldn/popup.py` | アプリでプログラムが表示する[ポップアップ](gui.md#pop-ups)。どれを表示するかは `pokeldn/app/popups.py` が決める |
| `pokeldn/pokemon.py` | PKHeX サービス、インポート、最終的なオファーの検証、受け取ったファイル |
| `pokeldn/gifts.py` | 共通の[ふしぎなおくりものファイル](gifts.md)の封筒、リーダー、ライター、ネイティブ形式への変換 |
| `pokeldn/receiver_gift.py` | 交換ホストが、本体のセーブデータ向けに作るふしぎなおくりもののポケモン ([受け取るプレイヤー向けに作る](gift_simulated.md#made-for-the-receiving-player)) |
| `services/pkhex/` | 固定された PKHeX.Core の依存関係。合法な出現の生成とゲームの互換性チェック |
| `pokeldn/ldn/` | 無線トランスポート、IP、Pia、信頼性、チャンネル表 |
| `pokeldn/online/` | [オンライン交換](online.md): リレー、マッチング、暗号化された相手とのチャンネル |
| `pokeldn/gba/` | GBA の無線通信プロトコル |
| `pokeldn/gen8.py`, `pokeldn/gen9.py` | 共通のポケモンのレコードのコーデック |
| `pokeldn/<game>/` | ゲームの識別情報、メッセージ、ステートマシン、プロトコル固有の差分 |
| `bin/` | パーサーとセッションのオーケストレーション |
| `gui/` | ビュー、ウィジェット、テーマ、ボードの操作部品 |

FRLG のプロファイル、アドバタイズ、ギフト設定は `pokeldn/frlg/` にあります。古い設定とコーデックの
インポートパスには、互換性のための小さなシム (shim) が残っています。

アプリは一度に 1 つのセッションだけを実行します。ボードは 1 つのプロセスにしか対応しないためです。Stop は、
実行中のセッションのツールにだけ表示されます。別のツールの Start は、そのセッションを停止して終了を待ってから
開始します。フラッシュもボードを占有し、Start はフラッシュが終わるまで待ちます。

## ポケモンの準備

共有サービスは、合法な出現を生成し、インポートを選択されたゲームの形式で保存します。各交換ランチャーは、
無線を開く前に渡されたファイルを準備します。
編集と要求された新しい識別情報は、適用後に検査されます。
形式が合わないもの、存在しない種族、違法な最終レコードは拒否されます。セッションのトレーナー識別情報は、
インポートしたポケモンの元のトレーナーを上書きしません。

PKHeX の `LegalityAnalysis.Parsed` は、解析が完了したかどうかを記録します。ヘルパーはこれを
`parsed` として返します。`parsed: false` の検査はヘルパーを再起動し、同じ要求を 1 回だけ繰り返します。
2 回目も解析が不完全なら、バリデータエラーを発生させます。レコードを拒否した完了済みの検査は、
拒否のまま残ります。サービスのロックは、最初の検査、再起動、再試行を通してかかります。

PID と暗号化定数の変更は、出現の相関を無効にすることがあります。特にイベントとレイドで顕著です。
新しい識別情報はオプトインで、PKHeX を通過しなければなりません。固定のイベントトレーナーは保持されます。
渡された状態では合法で、新しい識別情報では違法になるレコードは、自身の PID と暗号化定数を保持し、
ランチャーは `the offer kept its own PID` を記録します。ビルドは、その種族の他のすべての出現の後に
ふしぎなおくりものの出現を試します。そのため、野生・固定・タマゴの出現を持つ種族が、イベントとして作られることはありません。

組み立てられたポケモンは、出現をレコードに変換したものです。色違いは出現から要求されるため、第 3 世代の
PID は PKHeX が想定する RNG の相関を保ちます。単一の性別しかない種族は、出現からその性別を要求します。
メスしかいない Vespiquen や Froslass は、メスの Combee や Snorunt からしか得られません。
PID、個体値、そして野生スロットの場合はレベルはランダムに振られるため、出現は見送られるまでに最大 8 回
振り直されます。出現を進化させて到達した種族は、捕まえた状態で適合する出現がない場合、進化レベルまで
引き上げられます。進化したレコードは、進化後の種族が性別のない種族であれば、その性別を取り
(Nincada から得た Shedinja)、出現が持っていたフォルムを進化後の種族が持たない場合は、フォルム 0 になります
(Galarian Farfetch'd から得た Sirfetch'd)。

レベルまたは種族が変わった後に失敗したレコードは、段階的に修復されます。各段階は直前の段階の上に重ねられ、
最初に合法になった結果が残ります。

1. HOME 経由でしかゲームに届かなかったイベントのギフト (ソード・シールドの Zeraora と Melmetal) は、HOME トラッカーの設定が
   "made" のとき、HOME トラッカーを受け取ります ([HOME トラッカーの設定](gui.md#the-home-tracker-setting))。これは、イベントの
   固定の技を置き換えてしまう再適合より前に行われます。"empty" のもとではトラッカーは未設定のままになり、欠けたトラッカーが
   唯一の許容される問題です。
2. 技、再習得の技、TM と TR のレコードフラグ、plus-move フラグ、マスタリーフラグ、Pokemon LEGENDS アルセウスのサイズを
   再適合します。提案される技構成には、対応するレコードフラグがあるときにだけ合法になる TM と TR の技を含みます。
3. 進化したレコードの特性は、捕まえたときのスロットにおいて、進化後の種族のものに更新されます。
4. 取り扱いトレーナーのいないレコードには、2 人目として `POKELDN` が設定されます。交換進化のポケモンはすでに交換されており、
   一部のギフト (Pokemon LEGENDS Z-A の Magearna) は最初から取り扱い済みで届くためです。
5. 何かを数える進化 (急所に当たった回数、受けたダメージ、Rage Fist の使用回数、コイン) は、
   その数から始まります。
6. ブリリアントダイヤモンド・シャイニングパールで、Beauty の閾値 (Milotic、170) に達して起こる進化は、その Beauty と、
   poffins が示す最低の Sheen を設定します。

特性の更新を再適合より前に適用すると、Pokemon LEGENDS Z-A の Gholdengo が壊れます。そのため、順序は固定されています。

PKHeX が満たせない要求は、理由とともに拒否されます。最低の出現レベルより低いレベルを要求すると、そのレベルを報告します。
すべての出現が色違いにできない場合の色違いの要求は、その旨を報告します。ゲームに出現のない種族も、その旨を報告します。
固定レベルのギフトやイベント限定の種族には、より低いレベルの形はありません。
すべてのゲームのすべての種族を、6 種類の要求の形 (通常、色違い、レベル 50、レベル 100、レベル 50 の色違い、ニックネーム) で
走査すると、通常のビルドが失敗したものは次のとおりです:

| ゲーム | 種族 | 失敗 |
|---|---|---|
| ファイアレッド・リーフグリーン | 386 | 0 |
| Let's Go | 153 | 0 |
| Pokemon LEGENDS アルセウス | 242 | 0 |
| ブリリアントダイヤモンド・シャイニングパール | 493 | 2 |
| ソード・シールド | 664 | 2 |
| Pokemon LEGENDS Z-A | 364 | 1 |
| スカーレット・バイオレット | 733 | 31 |

2 件を除くすべての失敗は、そのゲームで PKHeX に出現がない種族です。ブリリアントダイヤモンド・シャイニングパールの Celebi と Deoxys、
ソード・シールドの Diancie と Meltan、スカーレット・バイオレットでは HOME からしか届かない伝説のポケモンです。出現がある 2 件は、
Pokemon LEGENDS Z-A の Milotic と、スカーレット・バイオレットの Wyrdeer です。PKHeX は Wyrdeer に第 9 世代の進化を与えません。
取り扱いトレーナーを持つ Feebas から組み立てた Z-A の Milotic は、
PKHeX の進化チェーンで Milotic 止まりになり、
ゲームのレコードはコンテスト能力を受け付けません。

フォルムを指定しない要求は、フォルムの順序で最初に組み立てられるものを取ります。
種族によっては、ゲームに後のフォルムでしか存在しないものがあります。

| ゲーム | 種族 | PKHeX が組み立てるフォルム |
|---|---|---|
| ソード・シールド | Zygarde | 10%-C, 50%-C (Power Construct) |
| ソード・シールド | Magearna | Original Color (イベント) |
| Pokemon LEGENDS アルセウス | Giratina | Origin |
| スカーレット・バイオレット | Ursaluna | Bloodmoon |
| Pokemon LEGENDS Z-A | Zygarde | 10%-C, 50%-C, Complete |
| Pokemon LEGENDS Z-A | Scatterbug, Spewpa | Garden, Meadow |
| Pokemon LEGENDS Z-A | Vivillon | Garden, Meadow, Marine |

### 出現の順序

組み立ては、PKHeX の出現 (`EncounterMovesetGenerator`) を、ゲームバージョンごとに 1 つずつ試します。
プレイヤー自身のバージョンを最初に、各バージョンの中では種類ごとに試します。

| 順番 | 種類 | その出現から組み立てられるレコード |
|---|---|---|
| 1 | 野生スロット | 捕獲: スロットの出会った場所とレベル、捕獲で許されるボール |
| 2 | 固定出現 | ギフト、伝説、レイド、またはダイマックスアドベンチャーのポケモン |
| 3 | ゲーム内交換 | NPC が交換するポケモン |
| 4 | タマゴ | 孵化: 孵化した場所で、親が渡したボールに入る |
| 5 | ふしぎなおくりもの | 他のすべての種類とバージョンの後: イベントの固定 PID により、ランチャーの新しい PID のオファーは違法になる |

PKHeX 自身の順序 (`EncounterMovesetGenerator.PriorityList`) は、タマゴを先頭に並べます。各種類は単独で、
最初の 80 件で打ち切られます。スカーレット・バイオレットでは 1 種族に最大 1806 件の出現が並び、上の順序では
587 種族のタマゴが 80 件目より後に並びます。すべての種族の通常のビルドは次のとおりです:

| ゲーム | 野生 | タマゴ | その他 |
|---|---|---|---|
| ファイアレッド・リーフグリーン | 170 | 147 | 69 |
| Let's Go | 142 | 0 | 11 |
| ブリリアントダイヤモンド・シャイニングパール | 402 | 38 | 51 |
| ソード・シールド | 384 | 6 | 272 |
| Pokemon LEGENDS アルセウス | 224 | 0 | 18 |
| スカーレット・バイオレット | 552 | 2 | 148 |
| Pokemon LEGENDS Z-A | 338 | 0 | 25 |

出現のレベルのまま残された進化済みのポケモンは、進化レベルより低いことがあります。すべての種族で、そのような組み立て 233 件のうち 231 件は、
合法な最低レベルから 100 まで、すべてのレベルで合法でした。そのため、レベル 100 で出現がその種族を運べるかが決まり、二分探索で最低のレベルを見つけます。
残りの 2 件は、
スカーレット・バイオレットの Hydrapple で、飛び飛びのレベルでのみ合法でした。

### オファーの選択肢

組み立てでは、フォルム、性格、特性、性別、持ち物、ボール、なつき度、最大 4 つの技、個体値、努力値も要求できます。
技とフォルムは、それを運べる出現に検索を絞ります。
性格、特性、性別、個体値は出現の条件に入るため、
レコードはそれらを伴って生成されます。第 3 世代の PID は、要求された性格を満たすように検索されます。
出現が別のものを振った場合、レコードはプレイヤーがそうするように要求へ動かされ、合法性の解析が結果を判定します:

| 異なる点 | 変更 |
|---|---|
| 性格 | Mint が能力の性格を設定します (第 8 世代以降) |
| 特性 | 特性を持つスロット (カプセルまたはパッチ) |
| 個体値 31 を要求された能力 | hyper training。レベル 100 (第 7 と第 8 世代) または 50 (第 9 世代) |
| フォルム | プレイヤーがフォルムを変えるもの (Rotom's appliances など) に設定 |

持ち物、ボール、なつき度、努力値は、組み立ての後に設定されます。第 3 世代と第 4 世代では、100 を超える努力値は、
出会ってから経験値を得たあとにのみ合法です。そのため、そのようなレコードには、次のレベルより下の経験値 1 が与えられます。
Pokemon LEGENDS アルセウスの努力値レベルは、保存された値に、個体値から来るバイアスを足したものです
(個体値 20 から 1、26 から 2、31 で 3)。保存された値がバイアスを引いた 10 を超えると違法なので、
要求はゲームに表示されるレベルとして受け取られ、バイアスが引かれます。

なつき度は元のトレーナーのもので、0 から 255 です。セーブデータの編集は、構築したとおりに書き込みます。交換で
ポケモンを受け取った本体は、プレイヤーが元のトレーナーである場合にのみそれを保持します。そのため、設定の「あなたのトレーナー」を
プレイヤー自身のものにしなければなりません ([あなたのトレーナー](gui.md#your-trainer))。PKHeX は、イベントのポケモンに対して、
イベント自身のもの以外のなつき度を拒否します。例として、ブリリアントダイヤモンドの Manaphy が挙げられます。

| タイトル | 受け取ったポケモンのなつき度 |
|---|---|
| ファイアレッド、リーフグリーン | 卵以外のすべてのポケモンで 70。トレーナーは問わない [trade_scene.c:1071] |
| Pokemon LEGENDS Z-A | プレイヤーの性別、ID、名前が元のトレーナーのものであれば保持されます。そうでなければ、プレイヤーが取り扱い者となり、種族の基礎なつき度になります ([受け取ったレコード](za.md#what-the-trade-writes-into-a-received-record)) |
| ブリリアントダイヤモンド | 元のトレーナーが受け取り直すと保持されます。別のトレーナーが受け取ると、取り扱い者のなつき度は 50 ([受け取ったポケモン](bdsp_trade.md#what-the-console-does-to-a-received-pokemon)) |
| Pokemon LEGENDS アルセウス、スカーレット | 別のトレーナーが受け取ると、取り扱い者のなつき度は 50 ([Pokemon LEGENDS アルセウス](pla.md#what-a-trade-rewrites), [スカーレット](sv.md#what-a-trade-rewrites)) |
| ソード | なつき度 255 で送られた Pichu は、受け取るプレイヤーの名前、ID、性別で組み立てられた場合は次のレベルアップで進化し、別のトレーナーの場合は進化しませんでした |
| Let's Go | 未計測 |

レコードは、すべての要求を運び、合法性の解析を通過しなければなりません。最初に当てはまる
[出現の順序](#encounter-order)の出現が採用されます。どの出現も運べない最初の要求は、
拒否の理由として示されます。

提示されるオプションは、そのゲームでその種族が持てるものに限られます。

| オプション | 表示される条件 |
|---|---|
| ボール | PKHeX が、その種族の少なくとも 1 つの出現に対してそれを許可するとき |
| 特性 | それを持つ合法な組み立てが存在するとき。Pokemon LEGENDS Z-A では一覧に出ない |
| 持ち物 | PKHeX が、そのゲームの解放済みの持ち物として一覧に出すとき。Let's Go と Pokemon LEGENDS アルセウスには持ち物がない |
| 努力値 | EV は各 252、合計 510。Let's Go の AV は各 200。Pokemon LEGENDS アルセウスの努力値レベルは各 10 |

各ゲームで 25 種族を抽出し、一覧に出たすべてのボール、すべての性格、固定の個体値、
固定の努力値、各性別、持ち物で組み立てると、8095 件中 8088 件が合法でした。PKHeX は、
ソード・シールドのイベントの Celebi で Hardy、Docile、Bashful を拒否し、
Pokemon LEGENDS Z-A のギフトの Melmetal では、同じ 3 つと Quirky を拒否します。

実機のソードで、カスタムのオプションで組み立てたポケモンを、次にキューに入った交換で戻すと、
オファーと同じレコードが保存されました ([オファーされたレコード](swsh_trade.md#the-offered-record))。
実機のブリリアントダイヤモンドとスカーレットでは、ニックネーム、性格、隠れ特性、性別、持ち物、ボール、
4 つの技、個体値、努力値を持つ色違いのレベル 37 の Pikachu が、サマリー画面に各オプションを表示しました。
交換で戻したブリリアントダイヤモンドのレコードは、12 個のフィールドすべてが一致しました。

### Showdown のセット

インポートの貼り付けは、PKHeX 自身のパーサー (`ShowdownParsing.GetShowdownSets`) で
Pokémon Showdown、Smogon、PKHeX のセットを読み取り、組み立てフォームに入力します。Build を押すと、
レコードが作られます。パーサーは、PKHeX が書き出すあらゆる言語 (英語、フランス語、ドイツ語、イタリア語、
スペイン語、日本語、韓国語、中国語) のセットを読みます。PKHeX 自身の綴りの外にある手入力のトークン
(例: `Nature : Rigide` に対する `Nature Rigide`) は、読めない行になります。チームの書き出しの
`=== [gen9] Team ===` ヘッダーは読み飛ばされます。テキストは Showdown の既定値に従い、`Level:` の行がなければレベル 100、
`IVs:` の行で省かれた個体値は 31 になります。パーサーは能力値を PKHeX の順序で保持し、Speed は 4 番目です。

| セットの内容 | 結果 |
|---|---|
| 読めない行、ゲームにない種族やフォルム、種族が持たない特性、ゲームが持てない持ち物、ゲームにない技、510 を超える EV | 理由とともに拒否され、何も入力されない |
| Tera Type、Gigantamax、Dynamax level、Hidden Power のタイプ | それなしで入力され、注記が付く |
| `IVs:` の行がない | 出現の個体値。パーサーは欠けた行を 31 が 6 つで埋めるが、野生の捕獲はそれを運べない |
| `Friendship:` の行がない | 出現のなつき度。Showdown は既定値 255 を省くため、セットはなつき度を明示したときだけ要求する |
| Let's Go や Pokemon LEGENDS アルセウスの EV、Pokemon LEGENDS Z-A の特性 | 注記とともに省かれる |
| 複数のセット、交換キュー内 | 各セットは、貼り付けられたピッカーから順に交換を埋める。その後の未使用のピッカーは再利用され、そうでなければキューの上限まで挿入される。入らないセットは注記に数えられる。どれか 1 つのセットが拒否されると、貼り付け全体が拒否される |
| 複数のセット、キューの外 | 最初のセットがフォームに入力され、注記が付く |

ソード・シールドのふしぎなおくりものは、PKHeX で WC8 のシールを検証し、対応する種族、フォルム、技、安全な
持ち物を確認します。
カスタムの WC8 カードは配布物であり、この構造の検査によって公式のイベントになるわけではありません。
任意の `--image` の調査検査は、ユーザーが用意したゲームのバイナリを使います。カードを配布するためには必要ありません。

### Let's Go の通信コード

Let's Go のホストのコードは 3 つのスロットです。スロットを開くと、本体の 10 個のピッカー用ポケモンが、
本体と同じく 5 つずつ 2 段で、名前を下に添えたスプライトとして表示されます。そのため、ダウンロードされなかった
スプライトでも読めます。選ぶとスロットが埋まり、次の空のスロットが開きます。値は `--code` が受け取るとおり、
カンマ区切りの 3 つの英語名です。Start は 3 つすべてが設定されるまで待ちます。空のスロットがあると、
ランチャーの既定のコードでホストされてしまい、本体の検索では見つからないためです。

### 交換キュー

1 つの席で複数の交換を完了させる入口を持つツールは、最大 6 体のポケモンを取ります。"Add a trade" は
ピッカーを追加し、セッションは完了した交換ごとに 1 体ずつ、順番にそれらを提示します。ピッカーは、
繰り返されるオファーのフラグになります。

| ツール | 提示の形式 | 最後の後の動作 |
|---|---|---|
| ファイアレッド・リーフグリーンのホストと参加 | パーティファイル、`--trades N`、スロット 0 から N-1 | ホストは、さらなる交換を拒否し (`PLAYER_CANCEL_TRADE`)、プレイヤーのキャンセルと「はい」を待つ。参加側はキャンセルして抜ける |
| Let's Go のホスト | `--offer`、その後の交換ごとに `--next-offer` | ランチャーは、さらなる交換に「いいえ」と答える (`pokeldn/lgpe/trade.py`)。プレイヤーが抜ける |
| Let's Go の参加 | `--offer`、繰り返し | ランチャーは、さらなる交換に「いいえ」と答える。プレイヤーが抜ける |
| ブリリアントダイヤモンド・シャイニングパールのホストと参加 | `--offer` / `--trade-template`、繰り返し | 最後のものが再び提示される |
| Pokemon LEGENDS アルセウスのホストと参加 | `--trade-box-record` / `--offer`、繰り返し。参加側はリストをホストの役割に渡す | 最後のものが再び提示される |
| スカーレット・バイオレットのホストと参加 | `--trade-offer`、繰り返し | ランチャーの交換段階が、さらなるメッセージに答えない (`pokeldn/sv/trade.py`、`done`) |
| ソード・シールドのホストと参加 | `--offer-file`、繰り返し。以降の各交換は同じセッションのボックスから実行される | 最後のものが再び提示される |
| Pokemon LEGENDS Z-A のホストと参加 | `--trade-offer`、繰り返し。各交換の開始時に、新しいレコードがプレビューされる | 最後のものが再び提示される。`--fresh-pid` のときは新しい PID で |

すべての交換ランチャーは、完了した交換ごとに 1 回 `pokeldn.ldn.show_done()` を呼びます。その呼び出しは、
各タイトルの上の表が終わる段階で行われます。ボードの LED を点滅させ、`[done] trade N complete` を出力します。
セッションパネルの Offering の帯はその行を数え、キューに入った最初の N 体のポケモンを交換済みとして示します。
受け取りリストはこの代わりにはなりません。一部のランチャーは、交換が完了する前に、本体がポケモンを選んだ時点で
本体のポケモンを書き込むためです。

`--fresh-pid` は、キューのすべてのレコードに独自の PID と暗号化定数を与えます。1 より大きい交換 N は、
受け取ったものを、拡張子の前に `-N` を付けた出力パスに書き出します (ファイアレッド・リーフグリーンでは `_tradeN_` と種族名、
スカーレット・バイオレットでは `.N`。これは異なるオファーで数えます。ブリリアントダイヤモンド・シャイニングパールのホストでは `_N`、
Pokemon LEGENDS Z-A とソード・シールドでは `-N`)。

### 実行の終了

交換の実行は、交換の後に本体が離れると自動的に終わります。そのため、うまく動いたセッションの後に
アプリの Stop が必要になることはありません。

| 役割 | 終了する条件 |
|---|---|
| ホスト、すべてのタイトル | 本体が、少なくとも 1 回の交換を完了した後にネットワークを離れたとき (`pokeldn.ldn.left_after_trade`)。交換の前に離れた本体は戻ってくることがあり、ホストは起動したままになる |
| ファイアレッド・リーフグリーンのホスト | 交換の後でも、そうでなくても、本体がネットワークを離れたとき |
| 参加側 | 本体のホストがネットワークを閉じるか役割を渡したとき (ファイアレッド・リーフグリーン、Let's Go、ソード・シールド、ブリリアントダイヤモンド・シャイニングパール)。スカーレット・バイオレット、Pokemon LEGENDS アルセウス、Pokemon LEGENDS Z-A は、何も交換しなかった席の後は再び検索し、交換した席の後は閉じる |

時間制限 (`--seconds`、`--hold`) は、本体が決して離れない実行にも、引き続き上限を設けます。

離脱の計測と未解決の問題は、各タイトルの Leaving の節にあります。

## ローカルのファイルとリリース

`config/host.toml` と実行時の参照メッセージは、追跡されます。`host.local.toml`、鍵、メモ、ログ、
調査用の画像、生成されたビルドの出力はローカルに置かれます。ROM のチェックサム比較には、明示的な
`--sum-reference` ファイルが必要です。本番の既定値は、`scratchpad/` やローカルの逆コンパイルからは読み込みません。

設定と用意されたオファーは、プラットフォームのアプリケーションデータフォルダーを使います。`POKELDN_DATA` は、
隔離された実行のためにそれを上書きします。受け取ったレコードは `.pk3`、`.pb7`、`.pk8`、`.pb8`、`.pa8`、`.pk9`、`.pa9` を使います。

設定からは、`pokeldn.app.storage` を通じて手動の掃除ができます ([ローカルストレージ](gui.md#local-storage))。
スキャンは、回収できるファイルの一覧を作ります。
削除はその一覧を使い、現在の選択を確認し直して、変更されたファイルは残します。
クリーンアップはアプリのビジー状態を保持するため、削除中はセッションもフラッシュも始められません。

パッカーは、追跡される実行時ファイル、公開された自己完結型の PKHeX 実行ファイル、そして ESP32、ESP32-S3、ESP32-C3、ESP32-C6 用の
統合された無線のファームウェアを取り込みます。欠けている画像があればビルドは止まります。
マシン固有の設定とメモは除外します。
Windows のビルドは、子プロセスのログと停止の処理のために標準入力と標準出力を保持し、
所有するコンソールは隠します。PyInstaller のウィンドウモードは、Windows でそれらのストリームを取り除きます。
Linux のアーカイブには、ポータブルな実行ファイルが含まれます。ビルドマシンのパスを含むデスクトップエントリーは省かれます。

## 検証

```sh
pip install -r requirements-dev.txt
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error -n auto --dist worksteal
```

CI は、これらのチェックを Linux、macOS、Windows で実行します。非公開の調査用フィクスチャは任意です。クリーンな
チェックアウトでは、それらなしで、出荷される参照データと共有の PKHeX サービスをテストします。

リリースのビルドは、凍結された実行ファイルに対して `scripts/check_app.py` を実行します。GUI のインポート、すべてのランチャー、
7 種類の PKHeX 形式、シリアルの検出、esptool を確認します。この検査にはキーや接続されたボードは要りません。
