# デスクトップ版ビルド

配布アプリには、PKHeX と、ESP32、ESP32-S3、ESP32-C3、ESP32-C6 向けの統合済みラジオファームウェアが含まれます。
`prod.keys` はユーザーが自分で用意します。

アプリを開き、Settings で `prod.keys` を選びます。Board ページで、ラジオとして使う USB ボードを選び、Wireless ファームウェアをインストールします。ゲームとツールを選び、ポケモンを用意するかファイルを選択してから、コンソールの指示に従って Start を押します。受け取ったポケモンは Settings で選んだフォルダーに保存されます。Output の横のフォルダーボタンで開けます。インストール時はチップを検出し、同梱のイメージを選びます。ファイルから読み込んだイメージは、書き込む前にそのチップと照合されます。S3、C3、C6 は、ネイティブの USB Serial/JTAG で接続します。S2 チップは扱えません。

ふしぎなおくりもののツールは、いずれも同じビルダーを共有します。プリセットを使うか、自分で組み立てるか、`.pokegift` ファイルを開きます。ソード・シールドでは `.wc8` カードも開けます。Save gift file は、ボードなしで選択中のおくりものを書き出します。書き出し形式は `.pokegift` で、拡張子に応じて `.wc3` (ファイアレッド・リーフグリーン) や `.wc8` (ソード・シールド) にもなります。[ふしぎなおくりものファイル](gifts.md#desktop-app) では、フォームの種類、カートリッジのバリエーション、ネイティブ形式への変換を説明しています。

## 初回起動

市松模様の背景はウィンドウ全体を覆い、透明なヘッダーも含みます。ナビゲーションレールは、ほかのパネルと同じくガラス調のパネルとして、その上に浮かびます。ヘッダーにはアプリのタイトルは表示されず、ドラッグとダブルクリックで最大化・元に戻すができます。macOS ではネイティブのウィンドウボタンが残り、Windows と Linux ではアプリのヘッダー内のボタンを使います。統合ヘッダーの見た目は macOS で確認済みです。Windows と Linux のウィンドウマネージャーの挙動は未検証です。

- macOS: アプリには署名がありません。一度開いて警告を閉じ、System Settings → Privacy & Security → Security で pokeldn の横にある Open Anyway を選びます。パスワードで確認します。
  2 回目以降は通常どおり起動します。
- Windows: zip を展開し、`pokeldn` フォルダー内の `pokeldn.exe` を実行します。その隣に `_internal` を置いたままにします。SmartScreen がアプリをブロックした場合は、More info → Run anyway を選びます。
  ボードに COM ポートが無い場合は [Windows の USB ドライバー](#windows-usb-drivers) を参照してください。
- Linux: ディストリビューションに含まれていない場合は GTK 3 と libsecret をインストールします。シリアル通信には `sudo usermod -aG dialout $USER` が必要です (Arch では `uucp`)。グループを変更したら、いったんログアウトして再ログインします。
  ポートが見つからない場合や brltty との競合については [Linux のシリアルポート](#linux-serial-ports) を参照してください。

## Android の設定要件

[Android 版アプリ](../examples/android/README.md) は、このインターフェースをスマートフォンで動かしたものです。その Board ページは下の表に従います。ボードを抜き差ししたとき、Android の USB 確認ダイアログが閉じたとき、プレイヤーが Settings から戻ったときに、USB の状態を読み直します。ネイティブ USB のボード (`303a:1001`) は、接続するとアプリを開きます。動作確認した OnePlus CPH2621 では、スマートフォンの OTG 接続設定を有効にすると、ケーブルを挿し直さなくても接続された ESP32C6 に給電され、認識されました。

| 検出された状態 | 必要な案内 |
|---|---|
| 対応する USB 機器がない | データ通信に対応したケーブルと接続を確認するよう案内します。スマートフォンの USB ホストや OTG 設定の手順を、OnePlus の OTG 接続トグルを含めて示します。機器が無いだけでは、どの確認で失敗したかは特定できません。 |
| 機器はあるが USB の許可がない、または拒否された | Android の USB アクセス確認について説明し、明示的な再試行を用意します。 |
| 許可済みだが、ボードのハンドシェイクに失敗 | ボードの接続と対応するラジオファームウェアを確認し、実際のエラーを表示します。 |
| ボードがハンドシェイクに応答 | 検出したボードとファームウェアを表示し、ゲームの手順に進めるようにします。 |
| ボードが切断された、またはユーザーが Settings から戻った | 検出と許可の状態を更新し、案内を書き直します。ボードの準備ができたら設定を再開します。 |

Silicon Labs CP210x ブリッジ (`10c4:ea60`) の従来型 ESP32 は、ブリッジのベンダー要求 (`UsbStream.java`) を通して動作します。CH34x や FTDI ブリッジのものは、スマートフォン版アプリでは動かせないものとして明記しています。PKHeX は Android 向けにコンパイルされ、スマートフォン上で動きます。受け取ったポケモンは、Android のファイルピッカーで保存します。

設定の案内には、動作確認済みのメーカー固有の経路か、検索できる設定名を使います。Android が対応している場合は、Settings へのショートカットも付けます。手順では次に行うべき操作を示し、設定の進み具合を表示し続けます。ADB や無線デバッグなどの開発者向けツールは、ユーザー向けの設定とは切り離しています。

Android では "Open the folder" を押すと、プレイヤーが選んだフォルダーを zip にして保存します。ファイル選択画面は Android 標準のものです。

## iOS の設定

[iOS 版アプリ](../examples/ios/README.md) は、このインターフェースを iPhone や iPad で動かしたものです。AltStore または SideStore でインストールします。iPhone は USB シリアルデバイスを開けないため、アプリはボードと Bluetooth で通信します。ボードには **Bluetooth wireless** ファームウェアを書き込みます。デスクトップ版アプリの Board ページから一度だけインストールし (ESP32-C6 は `pokeldn-radio-ble-c6.bin`、従来型の ESP32 は `pokeldn-radio-ble.bin`)、USB は給電にだけ使います。スマートフォンが接続すると、Board ページにはそのボードが "Bluetooth radio" として表示されます。初回起動時には Bluetooth へのアクセスを求められます。スマートフォンがボードを保持している間は、ボードは USB ケーブルの先で何も応答しません。コンピューターや Android スマートフォンからボードを使う前に、iOS 版アプリを閉じてください。ファイル選択画面は iOS 標準のもので、選んだファイルはアプリ内にコピーされます。アプリのファイルは、Files の On My iPhone 内の pokeldn にあります。

## スマートフォン

幅が 760 ポイント未満のとき、アプリはページを下部のタブバーで切り替えます。各ページのパネルは一度に 1 つずつ表示され、上の切り替えで選びます。Games ページでは Games、Options、Session を切り替えます。ツールを選ぶとそのオプションが前面に出て、Start を押すとセッションが前面に出ます。ダイアログは画面の幅いっぱいに広がります。Control ページと Update ページは、Android と iOS には表示されません。

## アプリの言語

Settings の App language には、英語とインストール済みのコミュニティ言語パックが並びます。パックを選ぶと有効になります。選択を反映するには、アプリを再起動してください。未翻訳の文字列は英語で表示されます。トレーナー言語の設定は、作成するポケモンの言語とは別に扱われます。[言語パック](plugins.md#language-packs-15) では、パッケージの形式と翻訳用テンプレートを説明しています。デスクトップ版アプリに同梱されているのは英語の既定値だけです。同梱のフォールバックフォント [Noto Sans CJK SC](https://github.com/notofonts/noto-cjk/tree/main/Sans/OTF/SimplifiedChinese) は、中国語・日本語・韓国語のテキストをオフラインで表示します。その SIL Open Font License は `gui/assets/fonts/LICENSE` にあります。

## あなたのトレーナー

Settings の Your trainer は、アプリが作るすべてのポケモンの親トレーナーです。名前、性別、言語、2 組の ID で構成され、ゲーム内に表示されるとおりに入力します。Pokemon LEGENDS Z-A では、受け取ったポケモンを自分のものとして扱うのは、親トレーナーの性別、ID、名前が一致する場合だけです ([受け取った記録](za.md#what-the-trade-writes-into-a-received-record))。Pokemon LEGENDS アルセウスのデータ交換の記録には、その性別と、それに合う見た目が含まれます ([記録](pla.md#the-games-reader-and-the-pre-handler-phase))。市販品の交換では、画面に相手の性別はどこにも表示されていませんでした。記録では、トレーナーを 16 ビットの TID と 16 ビットの SID として保存します。これは 1 つの 32 ビットの id の下位と上位の半分です。

| ゲーム | 表示される ID | シークレット ID | 保存される id |
|---|---|---|---|
| ファイアレッド・リーフグリーン | TID (0 から 65535) | SID (0 から 65535) | `SID << 16 \| TID` |
| Let's Go、ソード・シールド、ブリリアントダイヤモンド・シャイニングパール、Pokemon LEGENDS アルセウス、スカーレット・バイオレット、Pokemon LEGENDS Z-A | id を 10^6 で割った余り (6 桁) | id を 10^6 で割った商 (0 から 4294) | `secret * 10^6 + ID`、2^32 未満 |

Switch 向けの ID 組は、`pokeldn/app/settings.py` の `Settings.ids` でゲームごとに変換されます。Switch 向けの組が追加される前に保存された Settings は、最初の組から導出されます。そのため、それらから作った記録は同じ保存 id を保ちます。

ゲーム機に接続するツールはすべて、記録されたメッセージが持つ名前の代わりに、このトレーナーを自分のプレイヤーとして表示します (`tests/test_gui_catalog.py`)。ID は、ランチャーが受け取るすべての場所に渡されます。ファイアレッド・リーフグリーン、Let's Go、ソード・シールド、ブリリアントダイヤモンド・シャイニングパールです。ファイアレッド・リーフグリーンでは、第 3 世代の文字を 7 文字まで保持します。7 文字より長い名前は 7 文字に切り詰められ、第 3 世代の文字に含まれない名前は `POKELDN` になります (`Settings.name`)。

## Windows の USB ドライバー

従来型の ESP32 ボードは、USB ソケットの近くに記載された USB-シリアル変換チップを経由してコンピューターに接続します。Windows は、ブリッジのドライバーをインストールして初めてボードに COM ポートを割り当てます。ドライバーが無いと、ボードはアプリの一覧に表示されず、デバイスマネージャーには警告付きで表示されます (問題コード 28、ドライバーがインストールされていません)。ネイティブ USB ポートを使う ESP32-S3、C3、C6 のボードにはドライバーは不要です。

| ブリッジ | USB ID | ドライバー | インストール |
|---|---|---|---|
| Silicon Labs CP2102 / CP210x | `10c4:ea60` | [CP210x VCP ドライバー](https://www.silabs.com/developer-tools/usb-to-uart-bridge-vcp-drivers)、CP210x Universal Windows Driver の zip | zip を展開し、`silabser.inf` を右クリックして Install を選び、ボードを抜いて挿し直す |
| WCH CH340 | `1a86:7523` | [CH341SER.EXE](https://www.wch-ic.com/downloads/CH341SER_EXE.html) | 実行して Install を選び、ボードを抜いて挿し直す |

COM ポートが一覧に無いとき、Board ページは 2 秒ごとに、デバイスマネージャーで問題を持つ USB 機器を Windows に問い合わせます (`Get-CimInstance Win32_PnPEntity`、`ConfigManagerErrorCode <> 0`)。見つかった既知のブリッジの名前と、そのドライバーのインストール手順を表示します (`gui/board.py` の `bridges_without_driver`)。

## Linux のシリアルポート

アプリは root 権限もカーネルのネットワーク機能も使わず、ユーザーの権限でボードを開きます。ポートを開くには `dialout` グループ (Arch では `uucp`) が必要です。ユーザーが開けないポートは `EACCES` で失敗します。その場合、Board ページは使用中のポートではなく、そのグループを案内します。

| サービス | ボード | 影響 |
|---|---|---|
| brltty 6.4 (Ubuntu 22.04) | CH340 `1a86:7523` | `85-brltty.rules` が占有します。brltty がインストールされている間は `/dev/ttyUSB*` が現れません ([LP 1990357](https://bugs.launchpad.net/bugs/1990357))。対処: `sudo apt remove brltty` |
| brltty 6.6 (Ubuntu 24.04) | CP210x `10c4:ea60`、CH340 | CP210x のルールはコメントアウトされています ([LP 1958224](https://bugs.launchpad.net/bugs/1958224))。CH340 は `1a40:0101` ハブの背後でのみ占有されます |
| ModemManager 1.23 (Ubuntu 24.04) | すべて | `10c4`、`1a86`、`303a` の無視ルールがありません。その厳格なフィルターは、インターフェースのプロトコルが 1 から 6 の `cdc_acm` ポートだけを通します (`mm-filter.c`) |

Linux でシリアルポートが一覧に無い場合、Board ページは `/sys/bus/usb/devices` を読み取り、そのインターフェースの下に tty が無い既知のブリッジを指摘します。CH340 については brltty の対処も示します (`gui/board.py` の `bridges_without_port`)。

## ローカルストレージ

Settings の Storage には、回収可能なローカルファイルが占めている容量が表示されます。「Clear local files」は確認を求め、チェックに含まれるファイルを削除して、解放された容量を報告します。消去する前に、バグ報告に必要な記録を保存してください。

クリーンアップの対象は、アプリの `session/` 内の作業ファイル (キャプチャ、シリアルのトレース、一時的な提供、セッションのメタデータ)、`logs/`、そして `pokemon/` 内の未使用の生成済みまたは取り込み済みの提供です。作成から 1 分未満の提供は、ビルドがまだ終わっていない場合に選択内容を保存できるよう残されます。保存済みのツール設定やキューから参照されている提供は残ります。受信ファイルとその選択フォルダー、バンク、Switch の鍵、選択中のファームウェア、設定は、クリーンアップフォルダーに保存されている場合も保持されます。アプリが名前を付けた一時的な提供の外にあるポケモンの記録とバイナリダンプは、受信フォルダーが変わった後も残ります。生成された提供は、ビルダーのタイムスタンプとランダムな接尾辞で識別されます。シンボリックリンクは飛ばされます。チェック後に変更されたファイルは残ります。空のサブフォルダーは削除されます。

クリーンアップの前に、実行中のセッション、フラッシュ、ボードチェックを終えてください。クリーンアップはバックグラウンドで実行され、完了するまで新しいセッションとフラッシュを保留します。削除できなかったファイルは報告され、再試行できます。ポケモンのスプライトのキャッシュには、詳細設定の下に専用の Clear the cache ボタンがあります。

## セーブデータ

ファイアレッド・リーフグリーンのふしぎなおくりものツールの Your save タブは、Wonder Cards と Friend path を使うセーブデータを、コンソールからバックアップしたり、戻したりします ([セーブデータのバックアップと復元](frlg_gift.md#save-backup-and-restore))。セーブデータは `Documents/pokeldn/Saves` (`pokeldn.app.saves`) にあり、1 件ごとに `.sav` ファイルと、名前、取得元、コンソールのゲームコードを保持する `.json` で構成されます。「Clear local files」はこのフォルダーに触れません。`POKELDN_DATA` を設定している場合、ライブラリは代わりにそのフォルダー内の `Saves` になります。

| 操作 | 内容 |
|---|---|
| Switch からバックアップ | ランチャーが `backup-<run>.sav` とその `.json` を書き出します。リンクが途中で切れたバックアップは `Saves/.partial` に残り、次のバックアップはそこから続けられます |
| Switch へセーブデータを書き戻す | 選んだセーブデータが `--save-restore` に渡されます。1 つ選ぶまで Start はブロックされたままです |
| `+`、またはカードにドロップした `.sav` | ファイルがコピーされます。16 バイトのエミュレーター用フッターは取り除かれ、128 KB 以外のサイズは拒否されます |
| Rename、Export .sav、Delete | 名前は見た目だけのもので、`.json` に保存されます。Delete は、このコンピューター上の 2 つのファイルだけを削除します |
| 表示と編集 | PKHeX がトレーナー、手持ち、PC ボックスを読み込みます。下記を参照してください |

実行中、Session パネルはランチャーの `[save] backup N of 128 KB` または `[save] restore N of M sectors` の行を進捗バーとして描画します。実行が終わると、一覧が更新されます。

セーブデータに完全な複製がない場合、また PKHeX が手持ちのポケモンを不正と判定した場合、Restore anyway を有効にするまで復元はブロックされます。セーブデータの名前は、既定ではトレーナーとカートリッジの情報になります。その情報を知っているのはバックアップだけです。

エディターでは、トレーナーの名前、性別、お金、コインを変更できます。手持ちでは、並べ替え、削除、そしてこのセーブデータのトレーナー用に PKHeX が作ったポケモンの追加 (名前、ID、シークレット ID、言語) ができます。手持ちのポケモンごとに PKHeX の判定が表示されます。Check legality は 1 つのボックスについて実行します。数秒かかります。Keep as a new save は、結果を PKHeX を通して書き出します。PKHeX は、すべてのセクターのチェックサムを再計算し、ゲーム自身のセクターテストが通ることを確かめ、新しい項目としてライブラリに追加します。元のセーブデータは変更されません。

## バンク

Bank ページは、交換で受け取ったすべてのポケモンを保管し、HOME がそのポケモンを移せるどのゲームへも交換に出せます。記録は `Documents/pokeldn/Bank` (`pokeldn.app.bank`) に保存されます。各記録は、そのゲーム独自の形式 (`.pk3`、`.pb7`、`.pk8`、`.pb8`、`.pa8`、`.pk9`、`.pa9`) で 1 件ずつ、隣に `.json` を伴って保存されます。「Clear local files」を実行しても、このフォルダーには触れません。`POKELDN_DATA` を設定している場合は、代わりにそのフォルダー内の `Bank` が使われます。

| 段階 | 内容 |
|---|---|
| 交換が完了する | セッションパネルが受け取った各ファイルを PKHeX で読み込み、コピーをバンクに保存します。受信ファイルは残ります。バンクに既にあるバイト列は二重には保存されません |
| ポケモンがバンクに入る | その `.json` には、種族、概要、PKHeX の判定、元ファイル、バイト列の SHA-256、"made" の移動に使うランダムな 63 ビットの HOME トラッカー、`home_tracker` (`empty`、`made`、または空) が保存されます |
| 移動先が一覧に出る | ヘルパーの `destinations` コマンドが、7 つのゲームすべてへの移動を試し、拒否された場合はその理由をそれぞれ報告します |
| 移動先の交換ツールを選ぶ | ヘルパーの `move` コマンドが記録を変換します。結果は `"bank": id` 付きでそのツールの提供キューに加わり、アプリがツールを開きます |
| 実行の交換 N が完了する | `[done] trade N complete` の行で、交換 N としてキューに入っていたバンクのポケモンが取り除かれます。実行の終わりには、そのキューの項目も削除されます |
| 実行が失敗する、または先に停止する | ポケモンはバンクとキューに残ります |

移動は PKHeX 独自の HOME 変換 (`EntityConverter.ConvertToType`、`PKH` 経由) を通ります。その後、移動先のゲームで PKHeX の適法性チェックを受けます。移動先で合法でない移動は、PKHeX の理由付きで拒否されます。移動ごとの行は 1 つにまとめられ ("2 つの技が合法ではありません" など)、各問題は 1 回だけ表示されます。途中の処理は次のとおりです。

- 他のゲームからのポケモンは、[HOME トラッカーの設定](#the-home-tracker-setting) が指定するトラッカーを受け取ります。無し、またはバンクのもの。
- アプリのトレーナーが、移動先の保存データに移されるときと同じようにハンドラーになります (`IHandlerUpdate`、`PB8.UpdateHandler`)。自身のトレーナーを現在のハンドラーとしてもなお不正と判定された場合は、アプリのトレーナーが取り扱いトレーナーとして設定されます。ソード・シールドでは、これが求められます。
- 不正な技が残る移動では、移動先に対して PKHeX が提案する技の組み合わせを使います。
- PID、暗号化定数、親トレーナー、ID は保持されます。バンクのポケモンを提供する実行は、`--fresh-pid` を付けずに作られます。

| 拒否 | 出典 |
|---|---|
| FireRed/LeafGreen へは戻せない | `EntityConverter.IsConvertibleToFormat` |
| Let's Go へは送れない | HOME が Let's Go から取り込むだけです。`PK3` から `PB7` (Let's Go の形式、番号 7 は FireRed の 3 より上) への変換は、変換器だけが行います |
| 卵 | FireRed と LeafGreen 向けの HOME の画面。変換器はそれを孵化させてしまいます |
| 持ち物を持つ、または HM 技を覚えている FireRed/LeafGreen のポケモン | FireRed と LeafGreen 向けの HOME の画面 |
| 移動先に存在しない種族またはフォルム | 移動先の個体データ表 |
| 変換経路がない | PKHeX.Core 26.8.26 は、Legends Z-A の記録を他のゲームへ変換しません |

Edit で変えられるのは、プレイヤーがゲーム内で変更できる項目です。ニックネーム (空にすると種族名に戻ります)、レベル (上げるのみ)、技、持ち物です。ヘルパーの `check` コマンドは項目を適用し、PKHeX の適法性チェックを実行します。合法なポケモンを不正にしてしまう編集は拒否され、記録は元のままになります。保存された編集は記録と `.json` (概要、判定、SHA-256) を書き直し、移動先は再度チェックされます。交換待ちのポケモンは編集できません。

### HOME トラッカーの設定

PKHeX は、必要な HOME トラッカーを持たないポケモンを不正と判定します (`HomeTrackerUtil.IsRequired`、`LegalityCheckResultCode.TransferTrackerMissing`、重大度 `HOMETransferTrackerNotPresent`)。対象は、別のゲームへ移されたポケモンと、HOME を経由してしかそのゲームに届かなかった配布ギフトです。HOME 3.1.0 以降は、HOME が発行していないトラッカーを拒否します (エラー 10015)。Settings の詳細設定にある HOME tracker では、アプリがそこに入れるものを選びます (`Settings.home_tracker`)。`pokeldn.pokemon.Service` は、ヘルパーへのすべてのリクエストに `home_tracker` として付けて送り、実行は `POKELDN_HOME_TRACKER` として引き継ぎます。

| 設定 | バンクへの移動、取り込み、ビルダーのギフト修復 | 適法性 | 表示される警告 |
|---|---|---|---|
| `empty` (既定) | トラッカーは未設定のまま | PKHeX が、トラッカー付きで記録を合法と判定した場合は受け入れます。ほかの問題はすべて拒否されます | PKHeX が HOME トラッカーの欠落を示します |
| `made` | ランダムな 63 ビットのトラッカーを付けます。バンクのポケモンには、そのバンクのものを使います | 変わりません | HOME には預けられません |

ヘルパーの応答にはすべて `home_tracker` (`empty`、`made`、または空) が含まれ、`destinations` はゲームごとにそれを返します。警告は、作成または読み込んだ提供、バンクの項目、バンクの移動先、取り込みの行に表示されます。PKHeX 26.8.26 は、ほかのチェックをトラッカーの有無に左右させます。トラッカーが無いと、別の HOME ゲームでの進化を許しません (`EvolutionGroupHOME.CheckAllAdjacent`)。そのため、スカーレットでピチューとして孵化したピカチュウは、ソード・シールドでは不可能な進化と判定されます。また、Legends Z-A では、HOME が揃えた特性はトラッカー付きの記録でしか保持されません (`AbilityVerifier.VerifyBirthAbility`。ブラック 2 のミネズミの隠れ特性は `tests/data/bank_import.json`)。`empty` のもとでは、ヘルパーはそうした記録を、トラッカーを付けたコピーと、HOME が見たポケモンに加える変更 (`ValidWithTracker`) で判定します。記録そのものにはトラッカーは付きません。

ふしぎなおくりもの - Simulated もこの設定に従います ([ふしぎなおくりもの - Simulated](#mystery-gift---simulated))。ギフトのうち、PKHeX がトラッカーを求めるのは HOME が配布したものだけです。`empty` のもとではコピーにトラッカーは無く、`made` のもとでは作成されたトラッカーが付きます (`services/pkhex/Program.cs` の `MendGift`)。作成されたトラッカーには、HOME が見たポケモンに加える変更も伴います。PKHeX のチェックは、トラッカーを持つポケモンにそれを期待します [HomeQuirks]:
スカーレット・バイオレットのポケモンでは高さがスケールの値になり、Legends Z-A のポケモンでは高さと重さが対象になります。Legends Z-A のアルファはアルファマークを持ちます (`HomeSeen`)。PKHeX.Core 26.8.26 には、ソード・シールド向けに 16 件、ブリリアントダイヤモンド・シャイニングパール、Pokemon LEGENDS アルセウス、Pokemon LEGENDS Z-A 向けに各 4 件、スカーレット・バイオレット向けに 5 件のそうしたギフトがあり、どちらの設定でもすべてのギフトがチェックを通ります。ソード・シールドのふしぎなおくりものは、その 16 件をコミュニティのカードとして配布します (公式イベント、Pokemon HOME)。本体がポケモンを作るため、設定にかかわらずトラッカーは付きません ([Pokemon HOME](swsh_gift.md#pokemon-home))。

### 取り込み

Bank ページの + ボタン、またはグリッドにドロップしたファイルは、ポケモンのファイルまたはゲームのセーブデータを取り込みます。ヘルパーの `import` コマンドは PKHeX でファイルを読み込みます。まず `SaveUtil.TryGetSaveFile` を使い、ファイル名を手がかりにします (3DS のセーブは拡張子の無い `main` という名前のファイルです)。次に、PKHeX が扱えるあらゆる形式の単一の記録に対して `FileUtil.TryGetPKM` を使います (`.pk1` から `.pk9`、`.pb7`、`.pb8`、`.pa8`、`.pa9`、`.ck3`、`.xk3`、`.bk4`、`.rk4` など)。セーブデータでは、使用中の手持ちの枠を順に、続いて使用中のボックスの枠を順に取り込みます。ファイルは読み取るだけです。

| 記録 | バンクに保存される内容 |
|---|---|
| バンクが保持するゲームの記録 (`PK3`、`PB7`、`PK8`、`PB8`、`PA8`、`PK9`、`PA9`) | PKHeX が合法と判定した場合、記録をそのまま保存します。持ち物と技も含みます |
| その他の形式 | 持ち物を外した記録。ポケモンは持ち物なしで HOME に入るためです。第 3 世代と第 4 世代の記録では、HM 技も忘れさせます。パルパークとポケトランスファーがそれらを拒否するためです。その後 PKHeX が合法と判定した場合は、バンクの移動と同じように、最初に受け入れるゲームへ移動します。順序は、ファイアレッド・リーフグリーン、スカーレット・バイオレット、ソード・シールド、ブリリアントダイヤモンド・シャイニングパール、Pokemon LEGENDS アルセウス、Pokemon LEGENDS Z-A です |

PKHeX が自身の形式でも合法でないと判定した記録は、PKHeX の理由付きで拒否されます。移動の技の提案が、その記録のゲームで許されなかった技を代わりに認めることはありません。チェックサムが不正な記録、別のゲームの卵、どの到達可能なゲームにも存在しない種族も、同様に拒否されます。取り込んだポケモンの `.json` には `imported` が保存されます。ファイル名、枠、元の形式、取り除いた内容が含まれます。

`Bank/.imported` には、取り込んだ記録ごとに 1 つのキーが保存されます。キーは、何も取り除く前の、復号された保存バイト列の SHA-256 です。キーがある記録は、交換でバンクから取り出された後でも、再び取り込まれません。バイト列がすでにバンクにある記録は、二重には保存されません。ゲームをプレイした後に再び取り込んだセーブデータからは、変化した記録だけが取り込まれます。

ファイアレッドのセーブデータから取り込んだメタモンは、Bank ページから市販のスカーレットへの交換を完了しました。そのセーブデータを再び取り込んでも、その 104 件の記録はどれもバンクには保存されませんでした。

市販のソードから受け取った記録を、バンクのトラッカーと PID を保持したまま Legends Z-A へ移したところ、市販の Z-A の交換ボックスでレベルと親トレーナーが表示され、交換が完了しました。

`tests/test_bank.py` は、6 組のゲームの間で実際のヘルパーを通して記録を移し、移動先のランチャーがそれらを受け取ることを確かめます。あわせて、各拒否、保持されて拒否された編集、交換されたポケモンをバンクから取り出す実行も確かめます。ブラック 2 のセーブデータと、PKHeX のエンカウント生成器で作った第 4 世代と第 6 世代のファイルを取り込みます (`tests/data/bank_import.json`)。持ち物と HM は取り除かれ、不正な記録は拒否され、2 回目の取り込みでは何も保存されません。

### 未解決

- バンクが作成されたトラッカーを付けて移動したポケモンを、Pokemon HOME が受け入れるかどうか。HOME 3.1.0 以降は HOME が発行していないトラッカーを拒否し (エラー 10015)、作成されたトラッカーはその種類に当たります。
- 別のゲームへ移されたポケモンに、HOME が空のトラッカーを受け入れるかどうか。
- HOME 自身の FireRed/LeafGreen の取り込み規則が、その画面に表示される卵、持ち物、HM 技以外にも及ぶかどうか。
- Switch 版の FireRed/LeafGreen から取り込んだポケモンに HOME が表示する出自のアイコンを、どの記録の項目が持つか。カートリッジのポケモンを Pokemon Bank 経由で移したものには、それがありません (プレイヤーのスクリーンショットによる。ここでは未計測)。PKHeX.Core 26.8.26 は `.pk3` をパルパークの系統で変換するため、FireRed/LeafGreen からのバンクの移動は、HOME が書き出す記録と異なる可能性があります。

## GTS

GTS ページには、他のプレイヤーが公開している募集が、提供または求めているポケモンの種族で絞り込まれて並びます。自分の募集と申し出は Yours の下に表示されます。Deposit では、交換キューに入っていない適法なバンクのポケモンを預けます。募集の詳細には、それに応じられるバンクのポケモンがそれぞれ表示されます。募集または申し出の間、そのポケモンはバンクから外れ、`Documents/pokeldn/GTS` にあります。募集か申し出が存在すると、アプリは実行中であればどのページにいても応答します。イベントと規則は [GTS](online.md#the-gts) に記載されています。

## ボードとファームウェア

Board ページには、このコンピューターに接続されたすべてのボードが一覧で表示されます。選択したボードのヘッダーには、そのファームウェアとバージョンが表示されます。Up to date または Update available と表示され、その状態に必要な操作を 1 つ示します。Firmware カードには、アプリが同梱する各ファームウェアが並びます (`gui.board.FIRMWARES`: Wireless、次に Controller)。インストール済みのものには印が付き、チップが動かせないファームウェアはその旨が表示されます。それ以外のものは、確認の後にインストールされます。ファイルからのインストールでは、アプリ記述子のプロジェクト名で識別される pokeldn の `.bin` を選びます。

| ボード | ページの検出方法 | バージョンの取得元 |
|---|---|---|
| Wireless ファームウェア | そのシリアルポート | HELLO の応答 |
| Controller ファームウェア、従来型 ESP32 | ラジオの確認が失敗した後の、そのシリアルポート | ポート上のステータスフレーム |
| Controller ファームウェア、ESP32-S3 | USB バス (`0f0d:0092`: macOS では `ioreg`、Linux では `/sys/bus/usb/devices`、Windows では `Win32_PnPEntity`)。シリアルポートはありません | Bluetooth 経由で読んだステータス |
| pokeldn ファームウェアなし | 何も応答しない場合のシリアルポート | なし |

アプリが同梱するバージョンは、イメージの ESP-IDF アプリ記述子の `version` フィールドです (マジック値 `0xABCD5432`、統合イメージでは `0x10020` にあります)。Update available は、そのバージョンがボードのものより新しいことを意味します。シリアルポートへのインストールでは、esptool がチップをローダーモードにリセットします。Controller ファームウェアを動かす S3 では、ダウンロードコマンドを Bluetooth で送り、ローダーのポートが現れるまで最大 20 秒待ち、`--from-loader` で書き込みます。

## コントローラー

Control ページは、コントローラーファームウェアを動かすボードを通して Switch のボタンを押し、そのボード上でマクロを再生します ([コントローラーボード](hardware_pad.md))。Controller ファームウェアは Board ページ (ESP32-S3 または従来型 ESP32) からインストールします。ESP32-S3 は Switch の USB-C ポートに接続し、Connect は Bluetooth LE で接続します。従来型 ESP32 はこのコンピューターの USB に接続したままにし、Switch とは HOME の Controllers、Change Grip/Order からペアリングします。Connect はそのシリアルポート経由で接続します。ファームウェアを再インストールすると、ペアリングは消去されます。

ステータス行には、ボードがどこに接続されているかが表示されます。このコンピューターに接続されている (このコンピューターの USB バス上にある)、Switch に接続されている (USB が設定済みで、このコンピューターのバス上にない)、またはどちらにも接続されていない、のいずれかです。ファームウェアの `mounted` フラグは、何らかの USB ホストがボードを設定したことだけを示します。

| 部品 | 役割 |
|---|---|
| 画面上のコントローラー | ボタンを押し続けると、ゲーム機上でも押し続けた状態になります。スティックは最大に倒したとき 8 方向を取り、L3 と R3 はそれぞれの中心です |
| Keyboard | オンの間、キーはマクロの押下時間の間ボタンを押します。矢印キーで十字ボタン、X で A、Z で B、S で X、A で Y、Q で L、W で R、1 で ZL、2 で ZR、Enter で +、Backspace で -、H で HOME、C で Capture です |
| マクロへの記録 | 押すたびに、押していた長さを持つ 1 つの手順になります。次の押下までの間は、その手順の待ち時間になります |
| マクロエディター | ボタンとスティックを押す手順、待機、入れ子にできる繰り返し。1 回だけ実行する部分と、回数指定または停止まで繰り返す Loop 部分があります |
| ボードで再生 | マクロをコンパイルして読み込み、開始します。ボードは自身のクロックで再生し、コンピューターがスリープしたり切断されたりしても続けます |

Controller ファームウェアを動かすボードは、このコンピューターに接続されている間、Board ページに一覧表示されます。検出と変更の方法は [ボードとファームウェア](#boards-and-firmware) にあります。コントローラーが接続されていない場合、Control ページは接続されている機器を示し、Board ページへのリンクを表示します。

マクロは `Documents/pokeldn/Macros` に保存されます (`POKELDN_DATA` を設定している場合は、そのフォルダー内の `Macros`)。マクロは 1 件ごとに 1 つの `.pokemacro` ファイルとして、編集のたびに書き込まれます。Export は共有用にコピーを書き出します。Import はファイルを検査し、空いている名前でコピーします。形式は [コントローラーボード、マクロ](hardware_pad.md#macros) にあります。

接続が切れた場合 (コンピューターから Switch へ移る間にボードの電源が切れた場合)、ページは、ボードが応答するか Stop looking が押されるまで、ボードを探し続けます。

ページは `pokeldn.pad.service` と通信します。これは子プロセスで、`127.0.0.1:47800` で Bluetooth 接続を保持します。macOS は、アプリが `NSBluetoothAlwaysUsageDescription` を宣言していないと、Bluetooth を開くプロセスを停止します。配布版アプリはこれを宣言しています。宣言がない場合に止まるのは子プロセスだけです。子プロセスは、アプリが stdin を閉じると終了します。

macOS 26 では、`bluetoothd` はアプリバンドルのメイン実行ファイルとして署名されたバックグラウンドプロセスに、受動的な "ThirdPartyApp scan" を行わせ、サービス UUID フィルターの有無にかかわらず検出結果を返しません。署名されていない素のバイナリ (`Info.plist=not bound`) は、能動的なスキャンを受けます。そのため配布版アプリは、`Contents/Helpers/pokeldn-bluetooth` からサービスを起動します。これは実行ファイルのコピーで、その識別子で署名され、`_internal` は `../Frameworks` にリンクされています。アプリの Bluetooth 権限のもとで動きます。メイン実行ファイルからのスキャンでは 0 台の機器しか見つかりませんでしたが、ヘルパーからは 19 台見つかり、そのなかにボードも含まれていました。別のコードを動かしているサービスを見つけたアプリは (ステータス応答の `code`)、そのサービスに終了を指示し、自分のサービスを起動します。

## ポケモンのスプライト

ポケモンの画像は [PokeAPI](https://github.com/PokeAPI/sprites) から取得され、必要に応じてダウンロードされます。ダウンロードした画像はアプリのデータフォルダー内の `sprites/` にキャッシュされ、オフラインでも使えます。

Settings の Pokemon sprites を無効にすると、ダウンロードは止まります。キャッシュ済みの画像は引き続き表示されます。同じ設定セクションには、スプライトのキャッシュを消去するボタンがあります。

利用できない種族またはフォルムはプレースホルダーを表示します。色違いの画像が利用できない場合は、同じフォルムの通常の画像を表示します。画像が無くても、ポケモンの作成や交換はできます。

## レイドイベント

スカーレット・バイオレットのテラレイド (Host) ツールのレイドイベントカードは、Project Pokemon の [EventsGallery](https://github.com/projectpokemon/EventsGallery) からレイドを開催します ([イベントレイド](sv_raid.md#event-raids))。アプリは、ギャラリーのレイドイベントの独自コピーを、データフォルダー内の `EventsGallery/` (`pokeldn.app.events_gallery`) に保存します。「Clear local files」はこれを残します。

| 操作 | 内容 |
|---|---|
| Download | `api.github.com` に、`Released/Gen 9/SV/Raid Events` を変更した master の最新コミットを問い合わせ、`codeload.github.com/projectpokemon/EventsGallery/zip/<commit>` (22 MB、2026 年 10 月時点) をダウンロードします。各イベントの最新パッチの 4 つのテーブルを展開します (約 17 MB)。`gallery.json` にはコミットとその日付が保存されます |
| Check for updates | その最新コミットに対して 1 回だけ問い合わせます。コピーのものと異なる場合に更新があります。ギャラリーの他の場所での変更は対象外です |
| Update | もう一度ダウンロードします |

新しいコピーは、完了してから初めて古いものを置き換えます。ダウンロードが失敗したり取り消されたりした場合は、古いコピーが残ります。イベントのフォルダー名は 152 文字に達するため、Windows ではアプリはファイルを `\\?\` パスとして開きます。

イベント一覧には、コピー内のすべてのイベントが含まれます。ただし、ゲーム自身のテーブルである `000 Base Data` は除きます。2026-09-06 時点で 152 件あり、新しいものが先頭に並びます。横の矢印で並び順を切り替えます。各項目は、番号を除いたフォルダー名 (ラウンド、"Event · Round") の下にボスが並んだ形で表示されます。入力すると、両方で絞り込まれます。1 つ選ぶと次のとおりです。

- レイドカードには、イベントが出現するゲームバージョン (Paldea のみ)、選んだクリスタルが抽選される進行度が提示されます。また、クリスタルの代わりに、そのバージョンのイベント用クリスタルが提示されます。各クリスタルは、星の数とボスを持つ配布グループです ("7 stars: Charizard"、"4-5 stars: Florges, Mimikyu")。イベントが出現できない値は、最も近い出現可能な値に移ります (`raid_event.constrain`)。
- Find a raid は、イベントのクリスタルだけを検索します。段階ごとに 1 つの進行度を使い、ボスを種族として扱います。Rewards セクションは、イベント独自の報酬テーブルの項目と数量を提示します ([シードの探索](sv_raid.md#finding-a-seed)、`gui/views/reward_filter.py`)。Size mark の適格性では、選んだクリスタル、星の数、種族のどのボスも取れないマークをグレーアウトします ([サイズマーク](sv_raid.md#size-marks))。
- セーブデータで一度捕まえたボスを含むイベントには "Let it be caught again" (`--raid-catch-normal`) が表示されます。起動のたびに、また選んだイベントごとに、チェックは外れた状態になります ([イベントレイド](sv_raid.md#event-raids))。

カードを折りたたむと、そのイベントは脇に置かれます (ツールの値の `#raid-event-folded`、`GamesView.show_raid_event`)。レイドカード、Find a raid、コマンドは通常のレイドのものになり、ヘッダーには "Off: Event" と表示されます。展開すると、イベントが戻ります。使用中のイベントがあれば、起動時にカードが開きます。コピーにないイベント (未ダウンロード、または更新で消えたもの) は、選択されたままになります。ヘッダーには赤字で "Missing: Event" と表示され、コピーにそれが入るか、別のイベントが選ばれるまで、実行は拒否されます (`pokeldn.app.command.code_error`)。

## ホストのレイド報酬

テラレイド (Host) ツールの Rewards カードは、トレーニングアイテム、テラピース (ステラを含む)、ヘルバ・ミスティカ、お宝、ボールをテンプレートとして提示します。束を選ぶと、現在の報酬の行が置き換わります。その束に含まれるすべての行の数量は、1 から 999 までの値で一括変更されます。項目または個別の数量を編集すると、Custom rewards に切り替わります。行は最大 45 まで追加・削除できます。行が不完全な場合や数量が不正な場合は、起動できません。保存された選択では、項目と数量が保持されます。

Raid's own rewards は上書きを解除し、選んだレイドの報酬テーブルを使います ([ホスト](sv_raid.md#hosting)、`gui/views/rewards.py`)。

## レイド NPC パートナー

テラレイド (Host) ツールの Raid NPC partners カードは、Consoles joining の下にあり、コンソールが空けておく枠を埋める NPC トレーナーを選びます。コンソールが 1 台参加する場合は 2 人、2 台なら 1 人、3 台なら 0 人です ([パートナー](sv_raid.md#partners)、`gui/views/raid_partners.py`)。何も選ばれていない場合は何も渡されず、コンソールの場合と同じく、ホストがストーリーの進行度に応じたプールから選びます。

- パートナーの進行度: 解放される 5 段階 (Beginning を除く) のうち、ストーリーの進行度に応じた段階から始まります (黒いクリスタルの場合は 6 つ星、7 つ星のイベントレイドの場合は 7 つ星)。別の段階を選ぶと `--raid-partner-progress` を渡します。
- その段階のトレーナーは、1 行に 3 枚のカードで並びます。狭いウィンドウでは 2 枚です。カードには、トレーナーとポケモン、そのレベル (自分のポケモンのレベルの 5 分の 4、`command.raid_pokemon_level`)、テラタイプはチップとして並び、続いてその特性と 3 つの技が 1 行ずつ表示されます。レイダーが好むパートナーには、星と理由を添えた金または銀の帯が付きます ([お気に入りのパートナー](sv_raid.md#favoured-partners))。ツールチップには、より詳しい理由が表示されます。

クリックするとトレーナーが着席し、取る枠の番号が付きます。もう一度クリックすると、その枠は抽選に任されます。選んだ各パートナーは、選んだ順に `--raid-partner` を渡します。Consoles joining を上げると、最後に選んだものが外れます。選んだ段階にないパートナー (4 つ星未満の Dylan や Luke) は外れます。折りたたむとカードが隠れるだけです (`GamesView.show_raid_partners`)。選択は引き続きレイドに渡され、ヘッダーにその名前が表示されます。

## ユニオンサークル

スカーレット・バイオレットの 2 つのユニオンサークルのツールは、コンソールがホストするサークルに、4 桁のリンクコードで参加します ([ユニオンサークル](sv_union_circle.md))。サークルのコードは毎回新しくなるため、フィールドは起動のたびに空で始まります (`Field.remembered`)。

- Union Circle - Quests: Task は、残っている Snacksworth の伝説のポケモンをすべて解放するか、BP を与えます。BP の欄には 1 から 9,999,999 までを入力できます (`Field.bounds`)。コンソールの手順は、選んだタスクに従います。`(text, (flag, value))` として与えられた手順は、その欄が該当の値を持つ間だけ表示されます (`command.steps`)。Snacksworth の実行では、ホストのクリア数と、自分に不足しているクリア数を対比する棒グラフが描かれます ([進捗](#progress))。
- Union Circle - Encounters: 出現させるポケモンのカード (`gui/views/encounter.py`、フィールドの種類 `encounter`) で、種族、色違い、フォルム、レベル、テラタイプ、性格、性別、特性、持ち物、スケール、個体値を設定します。性格、特性、スケール、個体値を空のままにすると、ホストの野生のポケモンと同じように抽選されます。種族を変えると、その下の欄はリセットされます。既定で有効な Legal encounters only の状態では、カードは PKHeX の野生の枠が与える種族、フォルム、レベル、また PKHeX がどこかで受け入れるテラタイプを提示します。さらに、PKHeX がその出現を捕獲可能と認める場所をすべて一覧にします。どこでも認めない場合は、その理由を表示します。カードは `--spawn` と `--spawn-*` のフラグを渡します (`command.encounter_args`)。

組み込みの実行の `[panel]` カード ([ステータスカード](plugins.md#status-cards-18)) は、実行中、そのツールのオプションの上部に表示され、そこにだけ表示されます (`GamesView.show_run_cards`)。実行が終わると消えます。エンカウントの実行では、この方法でエリアの探索を表示します。

サークルの実行ログには、ユーザーが追える内容だけを残します。参加、ホストの合計、BP のクリア、出現したり戦ったりするポケモン、そしてホストのエリアの発見や喪失です。`--verbose-circle` (Advanced タブの Advanced options 内) を付けると、送信されたサークルのメッセージすべてと、エリア探索の各手順が加わります。

## ふしぎなおくりもの - Simulated

ふしぎなおくりもの - Simulated ツールのカードは、Let's Go、ブリリアントダイヤモンド・シャイニングパール、Pokemon LEGENDS アルセウス、スカーレット・バイオレット、Pokemon LEGENDS Z-A で、PKHeX のイベントテーブルからゲームのおくりものポケモンを一覧にします ([シミュレートされたふしぎなおくりもの](gift_simulated.md#the-gifts)、`gui/views/event_gifts.py`)。タイルは 1 行に 2 つずつ、新しいものが先頭に並びます。各タイルには、スプライト、カードのタイトル、ポケモンが表示されます。ポケモンには、その持ち主と配布された日時も添えられます。ホバーすると技が表示されます。一度に 24 件を表示し、Show more で同じ数だけ追加します。検索は、タイルに表示される任意の語 (ボール、技、カード番号) で絞り込みます。タイルが 10 件以下の場合はすべて表示されます。それ以上は、専用の枠内でスクロールします (`event_gifts.FIT`)。

クリックすると、設定のトレーナー用に新しいコピーが作られ、リストの上のキューに追加されます。適法性、技、OT も含まれます。1 回のホストセッションでは、おくりものを最大 6 件まで順に交換できます。同じイベントを何度でも選べ、選ぶたびに独自のコピーが作られます。開始前に、キュー内のおくりものは閉じるボタンで取り除けます。キューが満杯のあいだは、おくりものを取り除くまで、それ以上は選べません。コピーは作成時のトレーナーを保持します。トレーナーを変えたあとは、いったん取り除いて、おくりものを選び直してください。受け取り主の名前を持つのに、受け取り主の言語のセーブデータには届かないおくりもの (たとえば Let's Go の中国語版のメルタンとメルメタルは、ほかの言語のセーブデータには届きません) は、その理由を示す不正なタイルとして表示されます。タイルをクリックすると理由が示され、提供は残ります ([カードが届いたセーブ](gift_simulated.md#saves-a-card-reached))。既定で有効な Made for the receiving player (Advanced タブ) がオンの場合、交換は、コンソールの保存データのために、受け取り主の名前を持つおくりものを再び作ります ([受け取り主のための作成](gift_simulated.md#made-for-the-receiving-player))。カードのトレーナーが自身のものであるおくりものは、作成済みとして渡されます。キューのすべてのおくりものが作成済みとして渡される間、そのスイッチはオフになり、無効化されて薄く表示されます。その下の注記が理由を示します (`command.locked`)。その場合、起動時には `--for-receiver` は渡されません。受け取り主の名前を付けられるおくりものを含むキューでは、スイッチは設定されていた状態に戻ります。ホストは、それを対象となるカードのそれぞれに適用します。

HOME が配布したおくりもの (Let's Go 以外のゲーム) は、HOME トラッカーの設定が与えるトラッカーを持ちます ([HOME トラッカーの設定](#the-home-tracker-setting))。そのタイルは琥珀色の枠で囲まれ、選択されたコピーとして、設定の警告を表示します。警告は "PKHeX flags the missing HOME tracker" または "Can't be deposited in HOME" です。交換では、ほかのおくりものと同じく提示されます ([交換で提示されるコピー](gift_simulated.md#the-copy-a-trade-offers))。

Settings の Hide personal details in logs (既定で有効) は、アプリが表示・コピーするセッションログとボードログで、次の情報を伏せます (`pokeldn/app/redact.py`)。

| 伏せる対象 | 代わりに表示 | 残す内容 |

| MAC アドレスの機器側の半分 (コロンの有無を問わず) | `**:**:**`、`******` | ベンダー側の半分 (Nintendo、Espressif) |
| `ot_name`、`ht_name`、`OT`、`nickname`、`trainer`、`player`、`name` の後に続く引用符付きの値 (`'…'`、`"…"`、`b'…'`) | `***` | 大文字・小文字を問わず `POKELDN` と `PKLDN` (プログラム自身の名前) |

## ポップアップ

アプリが開始した実行、その子プロセスの別のもの、またはアプリ自身のコードは、表示中のどのページの上にもポップアップを出せます (`pokeldn.popup`、プラグイン API では 1.2 以降)。ポップアップは 3 種類あります。

| 種類 | ボタン | コールバック |
|---|---|---|
| `acknowledge(title, text)` | 1 つ、`label` (OK) | `on_ack`。ボタン、Esc、または外側のクリックで呼ばれます |
| `confirm(title, text, agree, disagree)` | agree と disagree。ラベルは呼び出し元が指定します | `on_agree`、`on_disagree`、または `on_dismiss` (Esc と外側のクリックで呼ばれます) |
| `choose(title, text, options)` (1.7) | 選択肢ごとに 1 つ、2 から 8 個。テキストの下に全幅で、呼び出し元の順に並びます | `on_choice(index)`、または `on_dismiss` (Esc と外側のクリックで呼ばれます) |

開くときは待ちません。ポップアップの id を返し、回答は後からコールバックとして届きます。コールバックは、アプリの回答を読むスレッドで実行されます。ただし `set_dispatcher(dispatch)` でプログラム自身のループに渡した場合は、そちらで実行されます。アプリでは、どのコールバックもウィンドウを止めないよう、ワーカースレッドで実行されます。例外を送出したコールバックは、そのトレースバックを表示します。

| オプション | 役割 |
|---|---|
| `id` | プログラム内でポップアップを識別します。開いたままのポップアップと同じ id で開くと、その場で置き換えられ、元のコールバックは破棄されます。指定しなければ新しい id が作られます |
| `tone` | `info`、`warning`、`error` のいずれかで、アイコンを決めます |

`cancel(id)` はポップアップを閉じます。`cancel` が戻った後は、そのコールバックは 1 つも呼ばれません。ただし、以前の回答がすでにディスパッチャーに渡しているものは除きます。未回答のポップアップを 32 個保持しているプログラムは、`RuntimeError` を受け取ります。ポップアップのヘッダーには、それを開いたプログラムの名前が表示されます。ツール、Board のインストーラー、Controller サービスの名前です。アプリ自身のポップアップには、何も表示されません。

プログラムが終了すると、その confirm と choose は閉じられ、acknowledge は、戻る回答がないまま残ります。アプリがない場合 (ターミナルのように `available()` が偽の場合)、ポップアップは出力中の `[pop-up]` の行になります。回答は届かず、32 個の数にも含まれません。

`runner.Process(..., popups=app.popups, label=...)` は、子プロセスで `POKELDN_POPUPS=1` を設定します。子プロセスは、各ポップアップを `[popup]` の行と JSON オブジェクトとして標準出力に送ります。アプリはそれをログから除き、別のスレッドの出力が行の途中に混ざっていても、その位置を見つけます。アプリは、子プロセスの標準入力に `[popup] {"id", "n", "answer"}` で回答します (選択肢の回答は選択肢の番号で、`"0"` から `"7"` です)。これは `pokeldn.app.runner.child` が読み取ります。`n` は、同じ id で開き直されたポップアップと区別するためのものです。そのため、置き換えられたポップアップへの遅い回答は何も発火させません。アプリ内のコードは、マネージャーに直接届きます (`popup.attach`)。`pokeldn.app.popups.Manager` は開いているポップアップを保持し、`gui.popups.Dialogs` がそれを描画します。アプリのダイアログの `page.pop_dialog()` は、アプリ自身の最上位のダイアログを閉じます。その上に開かれたポップアップを閉じることはありません。

## 進捗

実行は `[progress] DONE TOTAL UNIT TITLE` を出力します (`pokeldn.progress.show`、プラグイン API 1.7。`UNIT` は `bytes` または `items`)。これにより、ログの行の代わりに、Session パネルにバーが表示されます。表示内容は、量 (`1.05 of 5.20 GB`)、直近 30 秒の速度、残り時間です。`show` は、タイトルごとに 1 秒あたり最大 4 行まで出力し、最後の行は必ず出力します。セーブデータのバックアップや復元の `[save]` の行も、同じバーを描きます。

ふしぎなおくりもの - Simulated は、受け取り主のために作られたおくりものが、代わりに Settings のトレーナーで送られる場合に警告を出し、その理由を示します。理由は、セーブデータが誰の名前も持たないこと、またはそのコピーがカード、PKHeX、提供のチェック、ローダーのいずれかで止まったことです ([交換](gift_simulated.md#the-trade))。警告はコンソールごとに 1 つです (`receiver_gift.pop_up`)。新しい理由が出ると、開いている警告が置き換えられます。アプリは、インストールされなかった更新と、アプリが無効にしたプラグインについても、独自の警告を出します。

## アップデート

起動時、アプリはバックグラウンドで、5 秒のタイムアウト付きで `api.github.com/repos/Decryptu/pokeldn/releases/latest` に最新の安定版リリースを問い合わせます。アプリの `pokeldn.__version__` より新しいタグがあると、サイドバーに Update の項目が追加されます。それを開くとダイアログが表示され、リリースノートと、Update now または Download が出ます。

Update now (`pokeldn.app.update`) は、リリースをその場でインストールします。手順は次のとおりです。

1. このコンピューター用のアーカイブ (`pokeldn-macos-arm64.zip`、`pokeldn-windows-x64.zip`、`pokeldn-linux-x64.tar.gz`) と、リリースの `SHA256SUMS` を、データフォルダーの `update/` にダウンロードします。
2. `SHA256SUMS` の、そのファイル名に対応する行の SHA-256 と一致しないアーカイブは拒否します。
3. アーカイブを展開します。macOS では `ditto -x -k` を使います。これはバンドルのシンボリックリンクと権限を保持します。Linux では `data` フィルターを付けた `tarfile` を使います。Windows では `zipfile` を使います。
4. 新しいアプリを、ヘルパーとして起動します: `pokeldn --apply-update NEW TARGET PID VERSION` (`gui/updating.py`)。小さな "Updating pokeldn" ウィンドウは `update/helper.ready` に触れます。古いアプリは、そのファイルを検知すると終了します。ファイルがないまま 15 秒経つと、それでも終了します。これにより、ウィンドウが常に 1 つ画面に表示されます。
5. ヘルパーは、古いアプリのプロセスが終了するのを 120 秒待ちます。Windows では、インストール済みアプリ内に実行ファイルがあるすべてのプロセス (PKHeX のサービス) も待ち、10 秒後に残っているものを終了させます。インストール済みアプリは、隣で `.<name>.old` という名前に変更されます (Windows がフォルダーを解放するまで 30 秒間再試行します)。新しいアプリはその場所にコピーされ、古いコピーは削除され、新しいアプリが開きます。失敗した場合は、古いアプリを元に戻して開きます。ヘルパーのウィンドウが表示されたかどうかにかかわらず、入れ替えは実行されます。
   ヘルパーは、展開したコピーのフォルダーから実行されます。Windows は、どのプロセスかの作業フォルダーになっているフォルダーの名前変更を拒否します。エクスプローラーは、アプリを自身のフォルダーを作業フォルダーとして起動します。
6. 開いたアプリは `update/outcome.json` を一度だけ読みます。内容は "pokeldn updated to X"、または古いアプリが残った理由を示すダイアログです。ファイルを削除すると、ヘルパーは終了します (60 秒で諦めます)。その後アプリは、ヘルパーのプロセスが終わったあとに、展開したコピーと `.old` フォルダーを削除します。

アプリがダウンロードしたファイルには、隔離属性 (macOS) も Mark of the Web (Windows) も付きません。そのため、Gatekeeper も SmartScreen も再び確認を求めません。`SHA256SUMS` はアーカイブと同じ GitHub のリリースから取得されます。このチェックは、破損や途中で切れたダウンロードを検出しますが、リリース自体の真正性は検証しません。

| 状況 | 動作 |
|---|---|
| プレリリースまたはドラフト、または `vX.Y.Z` でないタグ | 提示しない |
| ネットワークなし、HTTP エラー、リリースではない応答 | 起動時には何も表示しない。Check now では GitHub が応答しなかったと表示 |
| Settings で Updates がオフ | 起動時に問い合わせない。Check now では引き続き問い合わせる |
| このコンピューター用のアーカイブがない、またはリリースに `SHA256SUMS` がない | Download はファイルまたはリリースページを開く |
| ソースチェックアウト、Downloads から実行された macOS アプリ (App Translocation)、ユーザーが書き込めない macOS または Linux のフォルダー | 理由とともに Download |
| Windows で、ユーザーが書き込めないフォルダー (`C:\Program Files`) | Update now。ヘルパーの起動前に Windows が管理者権限 (UAC) を求め、拒否するとアプリは変更されません |
| セッション、フラッシュ、またはクリーンアップが実行中 | Update now は、先にそれを終えるよう求めます |
| チェックサムの不一致、またはダウンロードの失敗 | 何も変わりません。ダイアログは Download を提示します |

管理者だけが変更できるフォルダーに置かれた Windows では、ヘルパーは `runas` 動詞を指定した `ShellExecuteExW` で起動します。結果は、展開したコピーの隣で読み書きされます (管理者のヘルパーは別のユーザーで動く場合があります)。新しいアプリはエクスプローラー経由で開くため、ユーザー自身の権限レベルで動きます。`scripts/check_update.py ARCHIVE FOLDER` は、パッケージ化されたアプリ自身のアップデートを、127.0.0.1 で配信されるリリースに対して実行します。Update check ワークフローは、Windows (ユーザーのフォルダーと `C:\Program Files`) と Linux で、Release 実行のアーカイブからこれを実行します。

Settings、鍵、受け取ったポケモンはアプリの外にあり、そのまま残ります。ヘルパーが `/Applications` のアプリを置き換えるときに、macOS が App Management の権限を求めるかどうかは未計測です。拒否された場合は古いアプリがそのまま残り、ダイアログにエラーが表示されます。

問い合わせにはユーザーのデータは含まれません。GitHub は、認証なしのリクエストを、アドレスごとに 1 時間あたり 60 件まで許可しています。`POKELDN_UPDATE_URL` は、テスト用に問い合わせ先を置き換えます (`tests/test_app_update.py`)。

## ファイルのドロップ

デスクトップからドラッグしたファイルは、次の対象に入ります。

| 対象 | 受け付けるもの |
|---|---|
| 交換で提供するポケモン | ポケモンのファイル (Or use a Pokemon file と同じく取り込まれます)、または Showdown セットの `.txt` (Import paste と同じく読み込まれます)。以降のファイルは後続の交換に渡されます |
| Add a trade | ファイルごとに新しい交換を 1 件。未使用の交換を末尾から埋め、セッションの上限まで追加します |
| ふしぎなおくりもののツールの Gift カード | `.pokegift`、または `.wc8` (ソード・シールド) か `.wc3` (ファイアレッド・リーフグリーン) のカード。Open a file に切り替わります |
| Board ページの Firmware カード | pokeldn の `.bin`。確認の後にインストールされます |
| どのパスのフィールド、ウェルカムダイアログ | そのフィールドが求めるファイル。フォルダーのフィールドでは、ドロップされたファイルのフォルダーを使います |

Flet 1.0.2 のデスクトップクライアントは、ファイルのドロップを受け付けません。`scripts/build_client.py` は、インストール済みのバージョンの Flet のソースをチェックアウトし、`gui/flet_drop` ([desktop_drop](https://pub.dev/packages/desktop_drop) を包む Flet の拡張) をそのクライアントに追加して、`gui/client/<platform>` にビルドします。`gui/drop.py` は、対応する `FileDrop` コントロールを宣言します。`gui/main.py` は、ビルド済みならそのクライアントを実行し、なければ Flet 自身のものを実行します。その場合、ドロップ先は表示されません。凍結されたアプリには、常にビルド済みのものが含まれます。このスクリプトには Flutter が必要です。バージョンは `python -m flet_cli.cli --version --json` が示すもの (Flet 1.0.2 では 3.44.8) です。macOS クライアントのデプロイターゲットは 11.0 から 12.0 に上げます。Xcode 27 は、それより古いものをビルドしないためです。Linux クライアントは、Flet 自身の CI がビルドするのと同じ light 版です。

## ドキュメントのページ

Docs ページには、アプリのガイドと、ナビゲーションに載っているこのサイトのすべてのページが表示されます。ページ一覧の上の検索欄は、セクション単位で一致します。各見出しとその下のテキストが対象で、クエリのすべての語が必要です。見出しまたはページタイトルに含まれる語は、上位に並びます。結果を選ぶと、その見出しの位置でページが開きます。`page.md#heading` へのリンクも、同じようにその位置へスクロールします (`gui/views/docs.py`)。

## 未公開のタイトル

Switch での発売に先立って用意されたタイトルは、ソースチェックアウトからアプリを実行している場合にのみ、ゲーム一覧、バンク、Docs ページに表示されます (`pokeldn/app/preview.py`)。配布版のリリースは凍結されていて `.git` を含まないため、それらが表示されることはありません。`POKELDN_PREVIEW=1` を設定すると、どこでも表示されます。`POKELDN_PREVIEW=0` を設定すると、チェックアウトでも非表示になります。そのドキュメントページは `nav_exclude` と `search_exclude` を設定しています。

## ソースから実行

ソース開発には、Python 3.13 と .NET 10 SDK をインストールします:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r gui/requirements.txt
dotnet build -c Release services/pkhex -warnaserror
python scripts/build_client.py    # optional: file drops; needs Flutter
python gui/main.py
```

ソースチェックアウトには、ファームウェアのイメージがありません (`gui/firmware` はビルドの出力です)。Board ページの Download the firmware は、従来型 ESP32 のイメージと `SHA256SUMS` を含む、最新の非ドラフトのリリースから既知のイメージをすべて取得します。各イメージはそのリリースの `SHA256SUMS` と照合され、すべて一致した場合にだけ書き込まれます。チップが対応する前のリリースには、そのチップのイメージはありません。チェックアウトより古いリリースのイメージは、古いシリアルプロトコルを持つ場合があります。その場合、ボードのチェックはファームウェアを古いものと報告します。

## デスクトップアプリのビルド

アプリをパッケージ化するには、`esp32`、`esp32s3`、`esp32c3`、`esp32c6` 向けの ESP-IDF v6.1 をインストールし、その環境を有効にします。4 つのラジオイメージは、それぞれ別の設定でビルドします。コントローラーのイメージ (`firmware/pad`) もビルドします。これはコンポーネントマネージャー経由で `espressif/esp_tinyusb` を取得します:

```sh
mkdir -p gui/firmware
POKELDN_IMAGES="$PWD/gui/firmware"
cd firmware/esp32
idf.py -B build/esp32 -D SDKCONFIG="$PWD/build/esp32/sdkconfig" set-target esp32
idf.py -B build/esp32 -D SDKCONFIG="$PWD/build/esp32/sdkconfig" build
idf.py -B build/esp32 merge-bin -o "$POKELDN_IMAGES/pokeldn-radio.bin"
idf.py -B build/esp32s3 -D SDKCONFIG="$PWD/build/esp32s3/sdkconfig" set-target esp32s3
idf.py -B build/esp32s3 -D SDKCONFIG="$PWD/build/esp32s3/sdkconfig" build
idf.py -B build/esp32s3 merge-bin -o "$POKELDN_IMAGES/pokeldn-radio-s3.bin"
idf.py -B build/esp32c3 -D SDKCONFIG="$PWD/build/esp32c3/sdkconfig" set-target esp32c3
idf.py -B build/esp32c3 -D SDKCONFIG="$PWD/build/esp32c3/sdkconfig" build
idf.py -B build/esp32c3 merge-bin -o "$POKELDN_IMAGES/pokeldn-radio-c3.bin"
idf.py -B build/esp32c6 -D SDKCONFIG="$PWD/build/esp32c6/sdkconfig" set-target esp32c6
idf.py -B build/esp32c6 -D SDKCONFIG="$PWD/build/esp32c6/sdkconfig" build
idf.py -B build/esp32c6 merge-bin -o "$POKELDN_IMAGES/pokeldn-radio-c6.bin"
export POKELDN_BLE=1   # the Bluetooth builds for the iOS app (hardware_esp32.md, Bluetooth)
BLE_DEFAULTS="sdkconfig.defaults;sdkconfig.defaults.ble"
idf.py -B build/ble -D SDKCONFIG="$PWD/build/ble/sdkconfig" -D SDKCONFIG_DEFAULTS="$BLE_DEFAULTS" set-target esp32
idf.py -B build/ble -D SDKCONFIG="$PWD/build/ble/sdkconfig" -D SDKCONFIG_DEFAULTS="$BLE_DEFAULTS" build
idf.py -B build/ble merge-bin -o "$POKELDN_IMAGES/pokeldn-radio-ble.bin"
idf.py -B build/ble-c6 -D SDKCONFIG="$PWD/build/ble-c6/sdkconfig" -D SDKCONFIG_DEFAULTS="$BLE_DEFAULTS" set-target esp32c6
idf.py -B build/ble-c6 -D SDKCONFIG="$PWD/build/ble-c6/sdkconfig" -D SDKCONFIG_DEFAULTS="$BLE_DEFAULTS" build
idf.py -B build/ble-c6 merge-bin -o "$POKELDN_IMAGES/pokeldn-radio-ble-c6.bin"
unset POKELDN_BLE
cd ../pad
idf.py -B build -D SDKCONFIG="$PWD/build/sdkconfig" set-target esp32s3
idf.py -B build -D SDKCONFIG="$PWD/build/sdkconfig" build
idf.py -B build merge-bin -o "$POKELDN_IMAGES/pokeldn-pad-s3.bin"
cd ../..
python scripts/build_client.py
python scripts/build_unicorn.py
python scripts/pack_app.py
```

イメージの出力先を絶対パスで指定するため、イメージは `gui/firmware` に置かれます。パッケージャーは、ラジオ、Bluetooth ラジオ、コントローラーのイメージ、`scripts/build_client.py` のクライアント、そして `scripts/build_unicorn.py` の Unicorn (CMake が必要) を必要とします。凍結されたアプリのチェックは、それらがすべて含まれていることと、同梱されたクライアントに `flet_drop` が含まれていることを確認します。リリースワークフローは、各ターゲットを個別にビルドし、すべてのイメージを各デスクトップ用パッケージャーに渡します。

アプリのバージョンは `pokeldn.__version__` です。Settings と、macOS および Windows のパッケージのメタデータに表示されます。リリースを準備する前に、これと `.github/release-notes.md` をあわせて更新してください。ワークフローは、3 つのデスクトップ向けダウンロードと 5 つのファームウェアイメージについて `SHA256SUMS` を作成します。手動のワークフロー実行はアーティファクトを作成します。`v*` タグは、`pokeldn vX.Y.Z` という名前のリリースを公開します。その本文は `.github/release-notes.md` で、先頭行は `# pokeldn X.Y.Z` である必要があります (ワークフローと `tests/test_release.py` が確認します)。毎回同じ 9 つのファイルが含まれます。ハイフンを含むタグ (例: `v0.3.0-rc1`) だけがプレリリースとして扱われます。GitHub は、リポジトリのサイドバーで、ほかの最新のリリースを Latest として表示します。

アプリは one-folder の PyInstaller ビルドです。macOS では `pokeldn.app`、Linux と Windows では `pokeldn` または `pokeldn.exe` と `_internal` を含む `pokeldn` フォルダーです。単一ファイルの場合、起動のたびにバンドル全体 (約 180 MB) が一時フォルダーに展開されます。すべての実行はアプリが自分自身を再起動するものなので、実行のたびにその展開を払っていました。M4 では one-folder のアプリは、Games ページを 2.9 秒ではなく 0.7 秒で開き、実行のプロセスは 1.5 秒ではなく 0.08 秒で開始します。Flet のパッケージャーは macOS で `--onedir` を拒否します。`scripts/pack_app.py` は、Flet 自身の `--onefile` の後にそれを PyInstaller に渡し、後の指定が有効になります。バンドルの Python プロセスは Dock に登録されません。前面のアプリとしては、アプリが終了するまで跳ねる 2 つ目のアイコンが表示されてしまいます。パッケージャーは `Info.plist` に `LSBackgroundOnly` を設定するため、単一ファイルのブートローダーの場合と同様に、Dock のアイコンはビューアーだけが持ちます。

| 部品 | サイズ | 小さく保つ仕組み |
|---|---|---|
| Flet ビューアー (`scripts/build_client.py`) | 31 MB。macOS のアーカイブでは 9.4 MB | オプションの Flet 拡張を含めない (動画、地図、カメラ、webview などはなし。アプリはコアのコントロールのみを描画します)。macOS ではビルドマシンのアーキテクチャのみ。Dart のシンボルを分離 (`--split-debug-info`)。macOS では xz アーカイブ |
| Unicorn (`scripts/build_unicorn.py`) | 3 MB | ARM と ARM64 のエンジンだけを使い、インストール済みのリリースをソースからビルドします。ホイールのライブラリはすべての CPU ファミリーを含みます (16 MB) |
| PKHeX ヘルパー (`services/pkhex`) | 16 MB | 完全なトリミング。ヘルパーが到達しないフレームワークと PKHeX.Core のコードは取り除かれます。EventSource、デバッガー、ホットリロードのサポートはオフです |
| Python | モジュール 8 MB | パッケージャーは、Flet の Web サーバー、認証、画像の追加機能 (`flet_web`、FastAPI、Uvicorn、Pydantic、httpx、Pillow)、pytest、Pygments、rich の構文、Markdown、トレースバックのモジュール、`multiprocessing`、`_pydecimal` を除外します。macOS では東アジアのコーデックも除外します。macOS のライブラリはローカルのシンボルを失います (`strip -x`) |

トリミングは .NET のリフレクションベースの JSON を無効にします。ヘルパーの応答はそれを必要とするため、プロジェクトではそれを再度有効にしています (`JsonSerializerIsReflectionEnabledByDefault`)。これがないと、すべてのコマンドが `JsonTypeInfo metadata for type 'System.String' was not provided` で応答します。第 3 世代のイベントテーブルは PKHeX.Core の内部にあり、名前で読み込まれます。`DynamicDependency` 属性により、トリミング後も保持されます。

macOS のパッケージャーは、ビューアーを Flet のファイル名 `flet-macos.tar.gz` のもとで xz として書き出します (13.6 MB ではなく 9.4 MB)。flet_desktop 1.0.2 はそのファイルを `r:gz` モードで開くため、凍結されたアプリは、圧縮形式を検出する `open` を持つ `tarfile` を flet_desktop に渡します (`gui/flet_client.py`)。実行ファイルと PKHeX ヘルパーは strip しません。どちらも Mach-O イメージの後ろにアーカイブを持つためです。Flet の macOS プロジェクトは、ビルドのたびに `dart run rive_native:setup` を実行します。Rive が無くなったため、この工程は失敗します。そのため、クライアントのビルドではそれを `exit 0` に置き換えます。

ビューアーは、ビルドごとに 1 回 `~/.flet/client/flet-desktop-full-<version>-<fingerprint>` に展開されます。Flet は、古いビルドのフォルダーを決して削除しません。起動のたびに、凍結されたアプリは自身のフォルダーに `pokeldn-drop` のマークを付け、そのマークを持つ他のフォルダーを削除します。また、以前の macOS ビルドの `pokeldn.app` も削除します (`gui/flet_client.py`)。ほかの Flet アプリのビューアーは残ります。

Flet 1.0.2 のパッケージャーは、macOS のビューアーを、既存の entitlements なしで再署名します。`scripts/pack_flet.py` のパッケージングラッパーは、メタデータを変更した後にビューアーに署名する際、それらを保持します。凍結されたチェックは、埋め込まれたビューアーから、署名された `com.apple.security.files.user-selected.read-write` entitlement を読み取ります。これがないと、`prod.keys` を選ぶときに `ENTITLEMENT_NOT_FOUND` が発生します。

Linux のブートローダーは `LD_LIBRARY_PATH` をバンドルのフォルダーに設定します。そのフォルダーには、ビルドマシンの `libstdc++.so.6` (Ubuntu 22.04) が入っています。これが先に読み込まれると、Fedora 44 の Mesa は EGL のクライアント拡張を持たなくなり、Flet ビューアーは libepoxy で異常終了します (`No provider of eglGetPlatformDisplayEXT`)。`pokeldn/app/paths.py` は、アプリが開始するすべてのプログラムに対して、ユーザーの `LD_LIBRARY_PATH` を復元し、`FLET_LINUX_DISTRO` を同梱ビューアーのビルドに設定します。そうしないと、Flet は glibc によってビューアーを選び、バンドルに含まれていないものをダウンロードしてしまいます。凍結されたチェックは、Linux でその両方を確認します。

アプリは、Check offline のために Unicorn をバンドルします。Unicorn はアーキテクチャのモジュールを名前で読み込むため、パッケージャーはそのサブモジュールを収集し、ARM だけのライブラリを、ホイールのファイル名のまま `unicorn/lib` に自ら追加します。凍結されたチェックは、ARM64 があり x86 がないことを確認します。PyInstaller の Windows ブートローダーは Control Flow Guard (DllCharacteristics `0xC160`) 付きでリンクされています。Unicorn は、最初の `uc_mem_map` で CFG のプロセスを `0xC0000409` により終了させます ([unicorn#2281](https://github.com/unicorn-engine/unicorn/issues/2281))。64 MiB のスレッドスタックでも変わりません。パッケージャーは `pokeldn.exe` から `GUARD_CF` を外し、`0x8160` (`python.exe` のフラグ) にします。凍結されたチェックは、すべてのプラットフォームで Unicorn の下でペイロードを実行します。そこでは Unicorn が自身のアクセス違反を発生させ、処理します。凍結されたチェックで `faulthandler` を有効にしないでください。その例外を stderr に記録し、チェックが失敗します。
